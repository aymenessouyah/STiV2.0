Keyframes, transformations & transitions

Vous allez rendre une page vivante : faire réagir un élément au survol avec transition, le déplacer avec transform, puis créer un mouvement autonome avec @keyframes. Chaque laboratoire ci-dessous affiche le code CSS exact de ce que vous manipulez : recopiez-le dans votre fichier style2.css.

01 Rappel express : transition ou animation ?

Deux outils, deux usages. Une transition ne fait qu'interpoler entre deux états déclenchés par un changement (survol, classe ajoutée, focus). Une animation décrit elle-même une suite d'étapes et peut tourner seule, en boucle.

Critèretransitionanimation + @keyframes
DéclencheurNécessaire : :hover, :focus, ajout de classe…Aucun : démarre au chargement de la règle.
Nombre d'étapes2 seulement (départ → arrivée).Autant que voulu : 0%, 50%, 100%…
RépétitionNon.Oui : animation-iteration-count: infinite.
SensRetour automatique à l'état initial.alternate, reverse, alternate-reverse.
Contrôle en cours de routeNon (on l'interrompt en changeant d'état).Oui : animation-play-state: paused.
Usage typiqueSurvol d'un bouton, ouverture d'un menu, changement de couleur.Chargement, rebond, pulsation, carrousel d'images.

Les deux syntaxes à connaître par cœur

/* 1 — transition : propriété durée fonction-accélération délai */
.animated-box{
  transition: background-color 0.5s ease;
}
.animated-box:hover{
  background-color: #f44336;
}

/* 2 — animation : nom durée fonction-accélération répétition sens */
.animated-box{
  animation: moveBox 2s ease-in-out infinite alternate;
}
@keyframes moveBox{
  0%   { transform: translateX(0); }
  100% { transform: translateX(150px); }
}

Astuce : une propriété animable doit accepter des valeurs intermédiaires. Les couleurs, les longueurs, opacity et les fonctions transform s'animent ; display et width: auto ne s'animent pas.

Dans l'ordre. Chaque énoncé est suivi d'un corrigé dépliable : cherchez d'abord, comparez ensuite.


    

      

        
Exercice 1 — La boîte qui change de couleur

        Facile
      

      

        
Dans page2.html, la boîte porte la classe animated-box. Faites passer son fond de #ff8a80 à #f44336 au survol, en 0,5 s, avec une vitesse régulière au début et à la fin.

        
    
          
  1. Déclarez la transition sur l'état normal ou sur l'état :hover ? Expliquez.
    2. 
          
  2. Écrivez la règle :hover.
    3. 
        

        

          Voir le corrigé
          


/* style2.css */
.animated-box{
  background-color: #ff8a80;
  transition: background-color 0.5s ease-in-out;
}
.animated-box:hover{
  background-color: #f44336;
}

            
La transition se déclare sur l'état normal : la propriété est alors active dans les deux sens, donc le retour à la couleur de départ est lui aussi animé. Placée seulement dans :hover, la transition ne s'appliquerait qu'à l'aller.

          

        

      

    


    

      

        
Exercice 2 — Le bouton qui se soulève

        Facile
      

      

        
Un bouton .btn doit « décoller » du papier au survol : il monte de 3 px, se décale de 3 px vers la gauche et son ombre portée grandit de 2 px. Le tout en 150 ms.

        

          Voir le corrigé
          


.btn{
  border: 2px solid #101728;
  box-shadow: 2px 2px 0 #101728;
  transition: transform .15s ease, box-shadow .15s ease;
}
.btn:hover{
  transform: translate(-3px, -3px);
  box-shadow: 5px 5px 0 #101728;
}

            
On anime transform et non top/left : la position réelle dans la page ne bouge pas, aucun voisin n'est déplacé, et le rendu est plus fluide.

          

        

      

    


    

      

        
Exercice 3 — Reproduire l'animation du cours

        Moyen
      

      

        
Créez l'animation officielle de l'activité : une boîte de 100 × 100 px qui glisse de 150 px vers la droite, en 2 s, avec une accélération douce au départ et à l'arrivée, qui se répète indéfiniment en aller-retour.

        
    
          
  1. Écrivez la déclaration animation en forme abrégée.
    2. 
          
  2. Écrivez les @keyframes correspondants.
    3. 
          
  3. Que se passerait-il sans le mot-clé alternate ? Et sans infinite ?
    4. 
        

        

          Voir le corrigé
          


.animated-box{
  width: 100px;
  height: 100px;
  background-color: #ff8a80;
  margin-top: 50px;
  animation: moveBox 2s ease-in-out infinite alternate;
}
@keyframes moveBox{
  0%   { transform: translateX(0); }
  100% { transform: translateX(150px); }
}

            

              Sans alternate, la boîte revient brutalement à sa position de départ à chaque fin de cycle (saut visible).
              Sans infinite, l'animation ne joue qu'une fois puis la boîte reste à l'état final — et encore, seulement si l'on a mis forwards.
            

          

        

      

    


    

      

        
Exercice 4 — Une animation en trois étapes

        Moyen
      

      

        
Le point de chargement d'une page doit faire des aller-retours plus rapides que l'exercice 3, avec une pause au milieu du trajet : la boîte part de 0, atteint 120 px au milieu de l'animation, marque un temps d'arrêt, puis revient à 0.

        

          Voir le corrigé
          


.chargement{
  animation: allerRetour 1.4s ease-in-out infinite;
}
@keyframes allerRetour{
  0%   { transform: translateX(0); }
  40%  { transform: translateX(120px); }   /* arrivée */
  60%  { transform: translateX(120px); }   /* pause : mêmes valeurs */
  100% { transform: translateX(0); }
}

            
Deux étapes qui portent exactement les mêmes valeurs produisent une pause. Utilisez des pourcentages croissants : 0% → 100%.

          

        

      

    


    

      

        
Exercice 5 — La carte qui se retourne

        Difficile
      

      

        
Une carte de visite a deux faces. Au survol, elle pivote autour de l'axe vertical en 0,6 s et révèle son verso. Le texte du verso ne doit pas apparaître en miroir.

        

          Voir le corrigé
          


<div class="carte">
  <div class="carte__interieur">
    <div class="face face--recto">Recto</div>
    <div class="face face--verso">Verso</div>
  </div>
</div>


.carte{ perspective: 900px; width: 220px; height: 140px; }
.carte__interieur{
  position: relative; width: 100%; height: 100%;
  transform-style: preserve-3d;
  transition: transform .6s ease;
}
.carte:hover .carte__interieur{ transform: rotateY(180deg); }
.face{
  position: absolute; inset: 0;
  display: grid; place-items: center;
  backface-visibility: hidden;   /* cache la face arrière */
  border: 2px solid #101728; border-radius: 12px;
}
.face--verso{ transform: rotateY(180deg); }  /* texte à l'endroit */

            
Trois clés : perspective sur le parent (effet de profondeur), transform-style: preserve-3d sur l'élément qui tourne, et backface-visibility: hidden pour ne pas voir le dos des faces.

          

        

      

    


    

      

        
Exercice 6 — Défi : respecter la préférence « mouvement réduit »

        Difficile
      

      

        
Certains utilisateurs désactivent les animations dans leur système (troubles vestibulaires, migraine). Proposez une règle qui neutralise vos animations tout en gardant le site lisible.

        

          Voir le corrigé
          


@media (prefers-reduced-motion: reduce){
  *, *::before, *::after{
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}

            
On ne supprime pas les propriétés : on ramène les durées à zéro. L'élément atteint donc immédiatement son état final, sans mouvement. Ne mettez jamais animation: none si l'état final est indispensable (par exemple un élément déplacé par l'animation).

          

        

      

    

  


  
  

    
06 Questions théoriques corrigées

    
Les questions de la fiche « Activité pratique n°2 — partie 2 », avec des réponses rédigées utilisables en classe.


    

      
Q1 — Rôle exact de infinite et alternate

      

        
infinite (animation-iteration-count) indique que le cycle se répète sans fin : le navigateur relance les @keyframes du début à chaque fin de cycle, indéfiniment.

        
alternate (animation-direction) inverse le sens à chaque cycle : le cycle 1 va de 0 % à 100 %, le cycle 2 de 100 % à 0 %, le cycle 3 de 0 % à 100 %… Le mouvement devient donc un aller-retour sans saut brusque.

        
Les deux se combinent : infinite alternate = va-et-vient perpétuel. Sans alternate, l'élément revient instantanément à sa position initiale à chaque redémarrage.

      

    


    

      
Q2 — Performance : transform: translateX() plutôt que margin-left

      

        
Modifier margin-left change la géométrie de la boîte : à chaque image, le navigateur doit recalculer la mise en page (layout ou reflow), puis repeindre (paint) et recomposer. Sur une animation continue, ce coût se répète 60 fois par seconde et peut provoquer des saccades, surtout sur mobile.

        
transform ne modifie pas la mise en page : la transformation est appliquée après le calcul du layout, généralement par le compositeur (GPU). Seules les couches concernées sont recomposées, ce qui donne une animation fluide et économe en énergie.

        
Autre avantage : le déplacement visuel n'affecte pas la place réservée dans le flux, donc les éléments voisins ne « sautent » pas.

      

    


    

      
Q3 — Différence fondamentale entre transition et @keyframes

      

        
Une transition est une réaction : elle n'existe que si une propriété change d'état (survol, focus, ajout de classe, redimensionnement). Elle n'interpole qu'entre deux valeurs, et revient à l'état initial dès que le déclencheur disparaît.

        
Une animation @keyframes est un scénario autonome : elle se déclenche d'elle-même au chargement de la règle, peut contenir plusieurs étapes, se répéter, s'inverser, se mettre en pause, et rester sur son état final avec animation-fill-mode: forwards.

        
En résumé : transition = effet entre deux états, piloté par l'utilisateur ou le script ; animation = séquence temporelle autonome et répétable, pilotée par le CSS.

      

    

  


  
  

    
07 Pièges, performance & accessibilité

    

      
❌ Animer displayImpossible : les valeurs sont discrètes, il n'existe pas d'état intermédiaire. Utilisez opacity + visibility, ou @starting-style / transition-behavior: allow-discrete sur les navigateurs récents.

      
❌ Mettre la transition sur :hoverL'animation ne se jouera qu'à l'aller ; le retour sera instantané. Déclarez-la sur l'état normal.

      
⚠️ transition: allPratique en démonstration, dangereux en production : toutes les propriétés changent, y compris celles modifiées par un script, et les performances chutent. Nommez les propriétés.

      
⚠️ will-change partoutÀ réserver aux éléments réellement animés, et à retirer ensuite : chaque couche GPU consomme de la mémoire.

      
✅ Les propriétés « bon marché »transform, opacity et filter sont les plus fluides. width, height, top, margin déclenchent un recalcul de la mise en page.

      
♿ AccessibilitéToujours proposer une variante @media (prefers-reduced-motion: reduce). Une animation ne doit pas dépasser 5 s de mouvement continu (règle WCAG 2.2.2) et ne doit jamais clignoter plus de 3 fois par seconde.

      
✅ Tester les états clavierCe qui est animé au :hover doit aussi l'être au :focus-visible, sinon les utilisateurs au clavier ne voient pas le retour visuel.

      
ℹ️ animation-fill-modeforwards conserve l'état final, backwards applique l'état initial avant le départ (utile avec un délai), both fait les deux.
