Construire une requête SQL

Pars de la question. Remplis les étapes dans l’ordre : la requête s’écrit à droite, et des remarques t’aident à la corriger.

Les 5 questions à se poser
ÉtapeQuestion à se poserMots-clés repérables dans l’énoncéClause obtenue
1Que veut-on afficher ?« afficher », « donner », « lister », « quel est »SELECT
2Dans quelles tables se trouvent ces informations ?noms d’entités : classe, élève, noteFROM + jointure dans le WHERE
3Faut-il filtrer des lignes ?« dont », « de la classe X », « supérieur à », « en 2025 »WHERE
4Faut-il calculer par paquet ?« par classe », « pour chaque », « moyenne / nombre / total de »GROUP BY + agrégat
5Faut-il filtrer sur le résultat du calcul ?« dont la moyenne dépasse », « ayant plus de 3 »HAVING

Étape finale : « du plus grand au plus petit », « trié par » → ORDER BY.

Deux cas particuliers : sous-requête et auto-jointure
SituationMots-clés repérables dans l’énoncéOutilOù dans la page
Il faut comparer à un résultat qu’on doit d’abord calculer« supérieur à la moyenne générale », « le meilleur », « qui ont au moins une… », « qui n’ont jamais… »Sous-requête : un SELECT entre parenthèsesÉtape 4 (WHERE) ou étape 6 (HAVING) : coche « sous-requête »
La même table intervient deux fois« deux élèves de la même classe », « plus âgé que », « les paires de… »Auto-jointure : deux copies de la table, avec des alias (e1, e2)Étape 2 : « Ajouter une copie d’une table »

Test : si un calcul doit être fait avant de comparer → sous-requête. Si on compare des lignes d’une même table entre elles → auto-jointure.

Règles : jointure écrite dans le WHERE sous la forme table1.a = table2.a · aucune fonction (COUNT, AVG…) appliquée à une colonne du WHERE : elle va dans le HAVING, ou dans le SELECT d’une sous-requête.
Schéma de la base

Une table par ligne : table(colonne1, colonne2). La clé primaire s’appelle id, la clé étrangère id_table.
