Corrigé Série 5 — Gestion d'un Hôtel (Gesthotel)

Modèle relationnel de la base de données Gesthotel :
• CHAMBRE (numch, prix, type) — type : 'S' (Simple), 'D' (Double), 'Q' (Quadruple)
• CLIENT (numcl, nom, adresse)
• RESERVATION (numr, #numch, #numcl, dateDebut, nbjours, pension) — numr auto-incrémenté, dateDebut de type DATETIME

I. Question 1 — Création de la Base de Données Gesthotel et des 3 Tables (LDD)

On crée d'abord les deux tables parentes CHAMBRE et CLIENT, puis la table enfant RESERVATION munie d'une clé primaire auto-incrémentée (AUTO_INCREMENT), d'un champ DATETIME et de deux clés étrangères : 

CREATE DATABASE Gesthotel;
USE Gesthotel;

CREATE TABLE CHAMBRE (
  numch VARCHAR(5) PRIMARY KEY,
  prix  DECIMAL(8,2) NOT NULL,
  type  CHAR(1) NOT NULL CHECK (type IN ('S', 'D', 'Q'))
);

CREATE TABLE CLIENT (
  numcl   VARCHAR(6) PRIMARY KEY,
  nom     VARCHAR(50) NOT NULL,
  adresse VARCHAR(50) NOT NULL
);

CREATE TABLE RESERVATION (
  numr      INT AUTO_INCREMENT PRIMARY KEY,
  numch     VARCHAR(5) NOT NULL,
  numcl     VARCHAR(6) NOT NULL,
  dateDebut DATETIME NOT NULL,
  nbjours   INT NOT NULL,
  pension   VARCHAR(10) NOT NULL,
  FOREIGN KEY (numch) REFERENCES CHAMBRE(numch),
  FOREIGN KEY (numcl) REFERENCES CLIENT(numcl)
);
Pourquoi cette solution ? Les notes de l'énoncé imposent trois contraintes : type IN ('S', 'D', 'Q') sur CHAMBRE, AUTO_INCREMENT sur la clé primaire numr, et le type DATETIME pour dateDebut (date et heure). On crée CHAMBRE et CLIENT avant RESERVATION pour que les deux clés étrangères (#numch et #numcl) référencent des tables déjà existantes.

II. Insertion des éléments dans CHAMBRE, CLIENT et RESERVATION (LMD : INSERT INTO)

On insère les 4 chambres, les 3 clients, puis les 6 réservations au format standard SQL 'AAAA-MM-JJ HH:MM:SS' : 

-- 1. Insertion des 4 chambres dans CHAMBRE
INSERT INTO CHAMBRE VALUES ('C01', 250, 'S');
INSERT INTO CHAMBRE VALUES ('C02', 250, 'D');
INSERT INTO CHAMBRE VALUES ('C03', 400, 'Q');
INSERT INTO CHAMBRE VALUES ('C04', 300, 'D');

-- 2. Insertion des 3 clients dans CLIENT
INSERT INTO CLIENT VALUES ('CL01', 'Ali Trabelsi',   'Ariana');
INSERT INTO CLIENT VALUES ('CL02', 'Alia Ben Ahmed', 'Tunis');
INSERT INTO CLIENT VALUES ('CL03', 'Sonia Kammoun',  'Sfax');

-- 3. Insertion des 6 réservations dans RESERVATION (numr est auto-incrémenté)
INSERT INTO RESERVATION (numch, numcl, dateDebut, nbjours, pension) VALUES
  ('C01', 'CL02', '2022-05-20 12:30:00',  3, 'PC'),
  ('C01', 'CL03', '2022-04-07 10:00:00',  5, 'DP'),
  ('C02', 'CL01', '2022-06-24 15:00:00', 10, 'ALLIN'),
  ('C03', 'CL01', '2022-06-24 15:00:00', 10, 'ALLIN'),
  ('C03', 'CL03', '2022-07-17 08:00:00',  7, 'PC'),
  ('C04', 'CL02', '2022-06-26 13:30:00',  4, 'DP');
Pourquoi cet ordre d'insertion ? Chaque réservation référence un code chambre (C01 à C04) et un code client (CL01 à CL03) : les tables mères CHAMBRE et CLIENT doivent donc être remplies avant RESERVATION.

III. Question 2 — Corrigé détaillé des 20 Requêtes SQL (Type & Justification de la solution)

Requête 1 : Afficher tous les Clients d'Ariana.
Type : Sélection simple (Restriction WHERE) 
SELECT *
FROM client
WHERE adresse = 'Ariana';
Pourquoi l'utilisation de cette solution ? Toutes les informations demandées (toutes les colonnes du client et son adresse) se trouvent dans la seule table client : aucune jointure ni sous-requête n'est nécessaire, un simple filtre WHERE adresse = 'Ariana' suffit.
Requête 2 : Donner le nombre de chambres par type de chambre.
Type : Regroupement (GROUP BY) & Agrégation (COUNT) 
SELECT type, COUNT(*) AS nb_chambre
FROM chambre
GROUP BY type;
Pourquoi l'utilisation de cette solution ? L'expression « par type de chambre » indique qu'il faut regrouper les lignes de la table chambre selon la colonne type ('S', 'D', 'Q') avec GROUP BY type et compter l'effectif de chaque groupe avec COUNT(*).
Requête 3 : Trouver les chambres qui coûtent le moins cher.
Type : Sous-requête scalaire (= SELECT MIN) Requête imbriquée 
SELECT *
FROM chambre
WHERE prix = (SELECT MIN(prix) FROM chambre);
Pourquoi l'utilisation de cette solution ? En SQL, on ne peut pas écrire WHERE prix = MIN(prix), et plusieurs chambres peuvent partager ce prix minimum (ici C01 et C02 à 250). On utilise donc une sous-requête imbriquée (SELECT MIN(prix) FROM chambre) qui calcule d'abord le tarif minimum, puis la requête principale affiche toutes les chambres ayant ce prix.
Requête 4 : Afficher une liste qui comprend le numéro de réservation, la date d'entrée et le nom du client.
Type : Jointure 
SELECT r.numr, r.dateDebut, cl.nom
FROM client cl, reservation r
WHERE r.numcl = cl.numcl;
Pourquoi l'utilisation de cette solution ? Le numéro de réservation et la date d'entrée sont dans reservation tandis que le nom du client est dans client : une jointure WHERE r.numcl = cl.numcl est indispensable pour associer chaque réservation à son client.
Requête 5 : Afficher le numéro de réservation et le nom du client pour les entrées : (5.1) d'aujourd'hui, (5.2) des 7 derniers jours, (5.3) d'il y a plus de 30 jours.
Type : Jointure + Fonctions de Date (NOW, DATE, DATE_SUB / DATEDIFF) 
-- 5.1 Entrées d'aujourd'hui (date de début = date système) :
SELECT r.numr, cl.nom
FROM client cl, reservation r
WHERE r.numcl = cl.numcl
  AND DATE(r.dateDebut) = DATE(NOW());

-- 5.2 Entrées passées au cours des 7 derniers jours :
SELECT r.numr, cl.nom
FROM client cl, reservation r
WHERE r.numcl = cl.numcl
  AND DATE(r.dateDebut) >= DATE_SUB(DATE(NOW()), INTERVAL 7 DAY);

-- 5.3 Entrées passées il y a plus de 30 jours :
SELECT r.numr, cl.nom
FROM client cl, reservation r
WHERE r.numcl = cl.numcl
  AND DATE(r.dateDebut) < DATE_SUB(DATE(NOW()), INTERVAL 30 DAY);
Pourquoi l'utilisation de cette solution ? Dans les trois cas, on affiche des colonnes issues de reservation (numr) et de client (nom), ce qui impose la jointure WHERE r.numcl = cl.numcl. Comme dateDebut contient aussi l'heure (DATETIME), on extrait la partie date avec DATE(r.dateDebut) pour la comparer à la date système DATE(NOW()) et aux intervalles de 7 ou 30 jours via DATE_SUB (ou DATEDIFF).
Requête 6 : Calculer le prix moyen des chambres.
Type : Agrégation globale (AVG sans GROUP BY) 
SELECT AVG(prix) AS prix_moyenne
FROM chambre;
Pourquoi l'utilisation de cette solution ? On demande une seule valeur globale sur toute la table chambre : la fonction d'agrégation AVG(prix) s'applique directement à l'ensemble des lignes sans GROUP BY.
Requête 7 : Calculer le prix moyen des chambres par type de chambre.
Type : Regroupement (GROUP BY) & Agrégation (AVG) 
SELECT type, AVG(prix) AS prix_moyenne
FROM chambre
GROUP BY type;
Pourquoi l'utilisation de cette solution ? Contrairement à la requête 6, la moyenne est ici demandée par type de chambre : on regroupe donc les chambres par type avec GROUP BY type afin que AVG(prix) calcule une moyenne distincte pour chaque catégorie ('S', 'D', 'Q').
Requête 8 : Lister toutes les réservations du client CL03.
Type : Sélection simple (Restriction WHERE) 
SELECT *
FROM reservation
WHERE numcl = 'CL03';
Pourquoi l'utilisation de cette solution ? Le code du client (numcl) est déjà présent comme clé étrangère dans la table reservation : on n'a donc pas besoin de joindre la table client, un simple filtre WHERE numcl = 'CL03' suffit.
Requête 9 : Calculer le montant total de la facture en cours du client CL03.
Type : Jointure + GROUP BY & Agrégation (SUM) 
SELECT R.numcl, SUM(ch.prix * R.nbjours) AS facture
FROM reservation R, chambre ch
WHERE ch.numch = R.numch
  AND R.numcl = 'CL03'
GROUP BY R.numcl;
Pourquoi l'utilisation de cette solution ? Le nombre de jours (nbjours) est dans reservation tandis que le tarif par nuit (prix) est dans chambre : il faut donc une jointure WHERE ch.numch = R.numch pour calculer le coût de chaque séjour (prix * nbjours), puis SUM(...) et GROUP BY R.numcl pour additionner toutes les réservations du client 'CL03'.
Requête 10 : Lister les noms des clients résidant actuellement à l'hôtel.
Type : Jointure + Calcul d'intervalle de Dates 
SELECT C.nom
FROM client C, reservation R
WHERE C.numcl = R.numcl
  AND DATE(R.dateDebut) <= DATE(NOW())
  AND DATE_ADD(DATE(R.dateDebut), INTERVAL R.nbjours DAY) >= DATE(NOW());
Pourquoi l'utilisation de cette solution ? Un client réside actuellement à l'hôtel si la date du jour DATE(NOW()) est comprise entre sa date d'arrivée DATE(R.dateDebut) et sa date de départ (DATE(R.dateDebut) + nbjours). Comme on veut afficher le nom du client, on relie client C et reservation R par la jointure WHERE C.numcl = R.numcl.
Requête 11 : Donner le nombre de clients qui ont choisi les mêmes pensions que le client CL02.
Type : Sous-requête (IN) Requête imbriquée + COUNT(DISTINCT) 
SELECT COUNT(DISTINCT numcl) AS nbrclient
FROM reservation
WHERE pension IN (
  SELECT pension
  FROM reservation
  WHERE numcl = 'CL02'
);
Pourquoi l'utilisation de cette solution ? On ne connaît pas à l'avance quelles pensions a choisies le client 'CL02' (il peut en avoir plusieurs). La sous-requête imbriquée récupère d'abord la liste des pensions de 'CL02', puis la requête principale utilise l'opérateur IN et compte les clients distincts avec COUNT(DISTINCT numcl) pour ne pas compter deux fois un même client.
Requête 12 : Afficher les réservations dont le séjour est supérieur à la moyenne des séjours.
Type : Sous-requête scalaire (> SELECT AVG) Requête imbriquée 
SELECT *
FROM reservation
WHERE nbjours > (SELECT AVG(nbjours) FROM reservation);
Pourquoi l'utilisation de cette solution ? Une fonction d'agrégation comme AVG(nbjours) ne pouvant jamais figurer directement dans un WHERE, on utilise une sous-requête imbriquée (SELECT AVG(nbjours) FROM reservation) qui calcule d'abord la durée moyenne, puis la requête principale filtre les réservations dont nbjours dépasse cette moyenne.
Requête 13 : Afficher les réservations dont le séjour est supérieur à celui de numr = 2.
Type : Sous-requête scalaire Requête imbriquée 
SELECT *
FROM reservation
WHERE nbjours > (
  SELECT nbjours
  FROM reservation
  WHERE numr = 2
);
Pourquoi l'utilisation de cette solution ? Pour comparer le nombre de jours de chaque réservation à celui de la réservation n° 2 sans coder la valeur en dur, on utilise une sous-requête qui extrait d'abord nbjours pour numr = 2, puis la requête principale sélectionne toutes les lignes ayant un nbjours strictement supérieur.
Requête 14 : Donner le nombre de réservations faites pour des chambres simples.
Type : Jointure + Agrégation (COUNT) 
SELECT COUNT(*) AS nb_reservations
FROM reservation R, chambre ch
WHERE R.numch = ch.numch
  AND ch.type = 'S';
Pourquoi l'utilisation de cette solution ? On compte des lignes de reservation, mais le critère « chambre simple » (type = 'S') se trouve dans la table chambre. On utilise donc une jointure WHERE R.numch = ch.numch suivie du filtre AND ch.type = 'S' et de COUNT(*).
Requête 15 : Calculer le nombre total de nuitées par chambre.
Type : Regroupement (GROUP BY) & Agrégation (SUM) 
SELECT numch, SUM(nbjours) AS nbrnuits
FROM reservation
GROUP BY numch;
Pourquoi l'utilisation de cette solution ? Le numéro de chambre (numch) et le nombre de nuitées (nbjours) sont tous deux dans la table reservation : aucune jointure n'est nécessaire, on regroupe par chambre avec GROUP BY numch et on additionne les durées avec SUM(nbjours).
Requête 16 : Calculer le chiffre d'affaires total par chambre (= total des nuitées * prix).
Type : Jointure + GROUP BY & Agrégation (SUM) 
SELECT R.numch, SUM(R.nbjours) * ch.prix AS chiffre_affaire
FROM reservation R, chambre ch
WHERE R.numch = ch.numch
GROUP BY R.numch, ch.prix;
Pourquoi l'utilisation de cette solution ? Les nuitées (nbjours) sont dans reservation alors que le tarif unitaire (prix) est dans chambre : il faut donc une jointure WHERE R.numch = ch.numch, puis un regroupement GROUP BY R.numch, ch.prix pour multiplier le total des nuitées SUM(R.nbjours) par le prix de la chambre.
Requête 17 : Afficher le nombre de réservations par client et pension.
Type : Regroupement sur 2 colonnes (GROUP BY) & COUNT 
SELECT numcl, pension, COUNT(*) AS nbreservation
FROM reservation
GROUP BY numcl, pension;
Pourquoi l'utilisation de cette solution ? Les deux critères de regroupement (numcl et pension) appartiennent à la table reservation. On regroupe donc sur le couple (numcl, pension) dans le GROUP BY et on compte le nombre de réservations de chaque couple avec COUNT(*).
Requête 18 : Lister les chambres dans l'ordre croissant des types et l'ordre décroissant des prix.
Type : Sélection avec Tri multicritère (ORDER BY ASC, DESC) 
SELECT *
FROM chambre
ORDER BY type ASC, prix DESC;
Pourquoi l'utilisation de cette solution ? Il s'agit d'un tri sur une seule table : ORDER BY type ASC, prix DESC trie d'abord les chambres par type croissant, puis, à type égal, de la plus chère à la moins chère.
Requête 19 : Lister les clients ayant effectué au moins 2 réservations.
Type : Jointure + GROUP BY / HAVING 
SELECT cl.numcl, cl.nom, cl.adresse, COUNT(r.numr) AS nbreservation
FROM client cl, reservation r
WHERE cl.numcl = r.numcl
GROUP BY cl.numcl, cl.nom, cl.adresse
HAVING COUNT(r.numr) >= 2;
Pourquoi l'utilisation de cette solution ? Pour afficher l'identité complète du client et compter ses réservations, on relie client et reservation par la jointure WHERE cl.numcl = r.numcl et on regroupe par client avec GROUP BY. Comme la condition « au moins 2 réservations » porte sur l'agrégat COUNT(r.numr) >= 2, on utilise obligatoirement la clause HAVING.
Requête 20 : Lister les chambres n'ayant aucune réservation enregistrée dans la base.
Type : Sous-requête (NOT IN) Requête imbriquée 
SELECT *
FROM chambre
WHERE numch NOT IN (
  SELECT numch
  FROM reservation
);
Pourquoi l'utilisation de cette solution ? On cherche les chambres absentes de la table reservation. Une jointure entre chambre et reservation ne montre que les chambres réservées ; il faut donc une sous-requête imbriquée (SELECT numch FROM reservation) combinée à l'opérateur NOT IN pour retenir les chambres qui n'y figurent jamais.
