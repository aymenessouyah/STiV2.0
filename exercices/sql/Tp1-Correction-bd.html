Corrigé Série 1 : Langage de Définition de Données (LDD)

I. Création des bases de données et des tables (LDD)

Rappel LDD : On crée toujours les tables mères (possédant les clés primaires référencées) avant les tables filles (contenant les clés étrangères FOREIGN KEY), puis on insère les enregistrements dans le même ordre.

CREATE DATABASE Hopital;
USE Hopital;

CREATE TABLE Patient (
    num_patient INT(10) PRIMARY KEY,
    nom_patient VARCHAR(20) NOT NULL,
    prenom_patient VARCHAR(20) NOT NULL,
    adr_patient VARCHAR(50)
);

CREATE TABLE Medecin (
    code_med VARCHAR(10) PRIMARY KEY,
    nom_med VARCHAR(20) NOT NULL,
    prenom_med VARCHAR(20) NOT NULL,
    tel_med INT(8),
    specialite VARCHAR(12) CHECK (specialite IN ('generaliste', 'chirurgien'))
);

CREATE TABLE Sejour (
    num_sej INT AUTO_INCREMENT PRIMARY KEY,
    num_chambre INT(4) NOT NULL CHECK (num_chambre BETWEEN 1 AND 1000),
    date_deb DATE NOT NULL,
    date_fin DATE CHECK (date_fin > date_deb),
    num_patient INT(10)
);

CREATE TABLE traite (
    num_patient INT(10),
    date_deb_trait DATE,
    code_med VARCHAR(10),
    PRIMARY KEY (num_patient, code_med),
    FOREIGN KEY (num_patient) REFERENCES Patient(num_patient),
    FOREIGN KEY (code_med) REFERENCES Medecin(code_med)
);

III. Corrigé détaillé — Exercice 1 (Système d'Information d'un Hôpital)

Ex1 - Q1 : Créer la structure des quatre tables (Patient, Medecin, Sejour, traite) en respectant les contraintes d'intégrité.
Type : LDD : CREATE TABLE + Contraintes
CREATE TABLE Patient (
    num_patient INT(10) PRIMARY KEY,
    nom_patient VARCHAR(20) NOT NULL,
    prenom_patient VARCHAR(20) NOT NULL,
    adr_patient VARCHAR(50)
);
CREATE TABLE Medecin (
    code_med VARCHAR(10) PRIMARY KEY,
    nom_med VARCHAR(20) NOT NULL,
    prenom_med VARCHAR(20) NOT NULL,
    tel_med INT(8),
    specialite VARCHAR(12) CHECK (specialite IN ('generaliste', 'chirurgien'))
);
CREATE TABLE Sejour (
    num_sej INT AUTO_INCREMENT PRIMARY KEY,
    num_chambre INT(4) NOT NULL CHECK (num_chambre BETWEEN 1 AND 1000),
    date_deb DATE NOT NULL,
    date_fin DATE CHECK (date_fin > date_deb),
    num_patient INT(10)
);
CREATE TABLE traite (
    num_patient INT(10),
    date_deb_trait DATE,
    code_med VARCHAR(10),
    PRIMARY KEY (num_patient, code_med),
    FOREIGN KEY (num_patient) REFERENCES Patient(num_patient),
    FOREIGN KEY (code_med) REFERENCES Medecin(code_med)
);
Pourquoi l'utilisation de cette solution ? On utilise CREATE TABLE avec PRIMARY KEY pour l'unicité, NOT NULL pour les champs obligatoires, CHECK (specialite IN (...)) et CHECK (num_chambre BETWEEN 1 AND 1000) pour les domaines de valeurs, et une clé primaire composée PRIMARY KEY (num_patient, code_med) dans la table d'association traite.
Ex1 - Q2 : Ajouter la colonne « Age » dans la table Patient (Numérique(2), Non nulle et >= 1).
Type : LDD : ALTER TABLE ... ADD
ALTER TABLE Patient
ADD Age INT(2) NOT NULL CHECK (Age >= 1);
Pourquoi l'utilisation de cette solution ? La structure de la table Patient existe déjà : on utilise donc ALTER TABLE Patient ADD ... pour ajouter une nouvelle colonne sans recréer la table, en lui associant les contraintes NOT NULL et CHECK (Age >= 1).
Ex1 - Q3 : Modifier la colonne « tel_med » de la table Medecin (type : texte, taille : 15).
Type : LDD : ALTER TABLE ... MODIFY
ALTER TABLE Medecin
MODIFY tel_med VARCHAR(15);
Pourquoi l'utilisation de cette solution ? La colonne tel_med existe déjà (initialement INT(8)) et on souhaite changer son type et sa taille sans changer son nom : on utilise ALTER TABLE ... MODIFY.
Ex1 - Q4 : Supprimer la colonne « tel_med » de la table Medecin.
Type : LDD : ALTER TABLE ... DROP COLUMN
ALTER TABLE Medecin
DROP COLUMN tel_med;
Pourquoi l'utilisation de cette solution ? Pour retirer définitivement un champ d'une table existante, on utilise la clause DROP COLUMN dans la commande ALTER TABLE.
Ex1 - Q5 : Ajouter la contrainte de clé étrangère entre « num_patient » de Patient (table mère) et « num_patient » de Sejour (table fille).
Type : LDD : ADD CONSTRAINT FOREIGN KEY
ALTER TABLE Sejour
ADD CONSTRAINT fk_sejour_patient
FOREIGN KEY (num_patient) REFERENCES Patient(num_patient);
Pourquoi l'utilisation de cette solution ? Une clé étrangère s'ajoute toujours sur la table fille (Sejour) et pointe vers la clé primaire de la table mère (Patient(num_patient)) afin de garantir l'intégrité référentielle.
Ex1 - Q6 : Ajouter la valeur par défaut « Tunis » à la colonne « adr_patient » de la table Patient.
Type : LDD : ALTER TABLE ... SET DEFAULT
ALTER TABLE Patient
ALTER adr_patient SET DEFAULT 'Tunis';
Pourquoi l'utilisation de cette solution ? On utilise ALTER adr_patient SET DEFAULT 'Tunis' (ou MODIFY adr_patient VARCHAR(50) DEFAULT 'Tunis') pour attribuer automatiquement la ville 'Tunis' lorsqu'aucune adresse n'est précisée à l'insertion.

IV. Corrigé détaillé — Exercice 2 (Agence de Location de Voitures)

Ex2 - Q1 : Créer la base de données « Gestion_Location ».
Type : LDD : CREATE DATABASE
CREATE DATABASE Gestion_Location;
USE Gestion_Location;
Pourquoi l'utilisation de cette solution ? La commande CREATE DATABASE crée le schéma de la base de données sur le serveur MySQL et USE la sélectionne comme base active.
Ex2 - Q2 : Créer les trois tables Client, Vehicule et Location avec leurs types et contraintes + Insertion d'exemples.
Type : LDD : CREATE TABLE + INSERT INTO
CREATE TABLE Client (
    NCIN_Cli VARCHAR(8) PRIMARY KEY,
    Nom_Cli VARCHAR(20) NOT NULL,
    Prenom_Cli VARCHAR(20) NOT NULL,
    Adresse_Cli VARCHAR(50),
    Ville VARCHAR(20)
);
CREATE TABLE Vehicule (
    Immat_vehicule VARCHAR(10) PRIMARY KEY,
    Marque VARCHAR(20) NOT NULL CHECK (Marque IN ('Peugeot', 'BYD', 'Fiat', 'Opel', 'Volkswagen', 'Citroen')),
    Model VARCHAR(20) NOT NULL,
    Annee_Acq YEAR NOT NULL
);
CREATE TABLE Location (
    Immat_vehicule VARCHAR(10),
    NCIN_Cli VARCHAR(8),
    Date_Loc TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    Duree_Loc INT CHECK (Duree_Loc > 0),
    Cout_Loc DECIMAL(10,3) CHECK (Cout_Loc > 0),
    PRIMARY KEY (Immat_vehicule, NCIN_Cli),
    FOREIGN KEY (Immat_vehicule) REFERENCES Vehicule(Immat_vehicule),
    FOREIGN KEY (NCIN_Cli) REFERENCES Client(NCIN_Cli)
);

INSERT INTO Client VALUES ('09876543', 'Mejri', 'Youssef', '12 Rue Liberté', 'Tunis');
INSERT INTO Vehicule VALUES ('215TU4520', 'Peugeot', '208', 2023);
INSERT INTO Location (Immat_vehicule, NCIN_Cli, Duree_Loc, Cout_Loc)
VALUES ('215TU4520', '09876543', 5, 450.000);
Pourquoi l'utilisation de cette solution ? On crée d'abord les deux tables mères Client et Vehicule, puis la table fille Location dont la clé primaire composée (Immat_vehicule, NCIN_Cli) référence les deux tables mères. Conformément au N.B., Date_Loc utilise TIMESTAMP DEFAULT CURRENT_TIMESTAMP.
Ex2 - Q3.a : Ajouter à la table Client un champ nommé Tel_Cli de type texte et de taille 10.
Type : LDD : ALTER TABLE ... ADD
ALTER TABLE Client
ADD Tel_Cli VARCHAR(10);
Pourquoi l'utilisation de cette solution ? On utilise ALTER TABLE Client ADD pour ajouter la colonne Tel_Cli de type chaîne variable VARCHAR(10).
Ex2 - Q3.b : Modifier le type de donnée de la colonne « Tel_Cli » de la table « Client » en numérique de 8 chiffres.
Type : LDD : ALTER TABLE ... MODIFY
ALTER TABLE Client
MODIFY Tel_Cli INT(8);
Pourquoi l'utilisation de cette solution ? On utilise MODIFY pour convertir le type de la colonne existante Tel_Cli de VARCHAR(10) en entier de 8 chiffres INT(8).
Ex2 - Q3.c : Supprimer la colonne « Adresse_Cli » dans la table « Client ».
Type : LDD : ALTER TABLE ... DROP COLUMN
ALTER TABLE Client
DROP COLUMN Adresse_Cli;
Pourquoi l'utilisation de cette solution ? La clause DROP COLUMN Adresse_Cli supprime la colonne de la structure de la table Client.
Ex2 - Q3.d : Vérifier que les valeurs de « Annee_Acq » dans la table « Vehicule » sont entre 2010 et 2026.
Type : LDD : ADD CONSTRAINT CHECK
ALTER TABLE Vehicule
ADD CONSTRAINT chk_annee CHECK (Annee_Acq BETWEEN 2010 AND 2026);
Pourquoi l'utilisation de cette solution ? On ajoute une contrainte de domaine CHECK (Annee_Acq BETWEEN 2010 AND 2026) avec ALTER TABLE Vehicule ADD CONSTRAINT pour interdire toute année hors intervalle.
Ex2 - Q3.e : Modifier la clé primaire actuelle de la table Location par la clé primaire composée (Immat_vehicule, NCIN_Cli, Date_Loc).
Type : LDD : DROP PRIMARY KEY + ADD PRIMARY KEY
ALTER TABLE Location
DROP PRIMARY KEY,
ADD PRIMARY KEY (Immat_vehicule, NCIN_Cli, Date_Loc);
Pourquoi l'utilisation de cette solution ? Une table ne peut avoir qu'une seule clé primaire : il faut d'abord supprimer l'ancienne (DROP PRIMARY KEY) puis définir la nouvelle clé composée de 3 colonnes (ADD PRIMARY KEY (...)) pour permettre au même client de louer le même véhicule à des dates différentes.
Ex2 - Q3.f à Q3.k : Supprimer la PK de Client, désactiver/réactiver les clés de Location, renommer Vehicule en Voiture, supprimer Client et la BD.
Type : LDD : DROP PK, DISABLE/ENABLE KEYS, RENAME, DROP
-- f. Supprimer la clé primaire de la table Client :
ALTER TABLE Client DROP PRIMARY KEY;

-- g. Désactiver les index/contraintes de la table Location :
ALTER TABLE Location DISABLE KEYS;

-- h. Réactiver les index/contraintes de la table Location :
ALTER TABLE Location ENABLE KEYS;

-- i. Renommer la table Vehicule en Voiture :
RENAME TABLE Vehicule TO Voiture;

-- j. Supprimer la table Client :
DROP TABLE Client;

-- k. Supprimer la base de données Gestion_Location :
DROP DATABASE Gestion_Location;
Pourquoi l'utilisation de cette solution ? Ces commandes couvrent tout le cycle de vie LDD : DROP PRIMARY KEY retire l'identifiant, DISABLE/ENABLE KEYS suspend puis rétablit la vérification des index, RENAME TABLE renomme l'entité sans perte de données, et DROP TABLE / DROP DATABASE suppriment définitivement la structure.
