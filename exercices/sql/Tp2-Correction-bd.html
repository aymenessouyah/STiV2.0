I. Création des bases de données et des tables (CREATE DATABASE / CREATE TABLE)

CREATE DATABASE BDDEPEMP;
USE BDDEPEMP;

-- Exercice 1 : Festival de Musique
CREATE TABLE Representation (
    Num_Rep INT PRIMARY KEY,
    titre_Rep VARCHAR(60) NOT NULL,
    lieu VARCHAR(50) NOT NULL
);
CREATE TABLE Musicien (
    Num_mus INT PRIMARY KEY,
    nom VARCHAR(50) NOT NULL,
    Num_Rep INT REFERENCES Representation(Num_Rep)
);
CREATE TABLE Programmer (
    Date DATE,
    Num_Rep INT REFERENCES Representation(Num_Rep),
    tarif DECIMAL(8,2),
    PRIMARY KEY (Date, Num_Rep)
);

-- Exercice 2 : Départements (DEPT) et Employés (EMP)
CREATE TABLE DEPT (
    DNO INT PRIMARY KEY,
    DNOM VARCHAR(30) NOT NULL,
    DIR INT,
    VILLE VARCHAR(30)
);
CREATE TABLE EMP (
    ENO INT PRIMARY KEY,
    ENOM VARCHAR(30) NOT NULL,
    PROF VARCHAR(30),
    DATEEMB DATE,
    SAL DECIMAL(10,2),
    COMM DECIMAL(10,2),
    DNO INT REFERENCES DEPT(DNO)
);

III. Corrigé Exercice 1 — Festival de Musique (Requêtes 1 à 6)

Ex1 - Q1 : La liste des titres des représentations.
Type : Projection simple
SELECT titre_Rep
FROM Representation;
Pourquoi l'utilisation de cette solution ? Toutes les informations demandées se trouvent dans une seule colonne (titre_Rep) d'une seule table (Representation) : une projection simple suffit.
Ex1 - Q2 : La liste des titres des représentations ayant lieu au « théâtre Municipal ».
Type : Sélection simple
SELECT titre_Rep
FROM Representation
WHERE UPPER(lieu) = 'THEATRE MUNICIPAL';
Pourquoi l'utilisation de cette solution ? On filtre les lignes de la table Representation avec la clause WHERE sur la colonne lieu en utilisant UPPER() pour ignorer la casse.
Ex1 - Q3 : La liste des noms des musiciens et les titres des représentations auxquelles ils participent.
Type : Jointure
SELECT M.nom, R.titre_Rep
FROM Musicien M, Representation R
WHERE R.Num_Rep = M.Num_Rep;
Pourquoi l'utilisation de cette solution ? Le nom du musicien est dans Musicien et le titre du spectacle dans Representation : on utilise une jointure dans WHERE sur la clé commune R.Num_Rep = M.Num_Rep.
Ex1 - Q4 : La liste des titres des représentations, les lieux et les tarifs du 25/01/2022.
Type : JointureType : Date
SELECT R.titre_Rep, R.lieu, P.tarif
FROM Programmer P, Representation R
WHERE P.Num_Rep = R.Num_Rep
  AND P.Date = '2022-01-25';
Pourquoi l'utilisation de cette solution ? Le tarif et la date sont dans Programmer tandis que le titre et le lieu sont dans Representation : on combine une jointure P.Num_Rep = R.Num_Rep et un filtre sur la date.
Ex1 - Q5 : Le nombre des musiciens qui participent à la représentation n°20.
Type : Agrégation COUNT
SELECT COUNT(*) AS nb_musiciens
FROM Musicien
WHERE Num_Rep = 20;
Pourquoi l'utilisation de cette solution ? Le numéro de représentation Num_Rep figure déjà comme clé étrangère dans Musicien : nul besoin de jointure, on filtre WHERE Num_Rep = 20 et on compte avec COUNT(*).
Ex1 - Q6 : Les représentations et leurs dates dont le tarif ne dépasse pas 20 DT.
Type : Jointure
SELECT R.Num_Rep, R.titre_Rep, P.Date
FROM Representation R, Programmer P
WHERE R.Num_Rep = P.Num_Rep
  AND P.tarif <= 20;
Pourquoi l'utilisation de cette solution ? On relie Representation et Programmer par la condition de jointure R.Num_Rep = P.Num_Rep et on filtre les tarifs inférieurs ou égaux à 20 DT.

IV. Corrigé Exercice 2 — Base BDDEPEMP : Départements & Employés

Ex2 - Q3 & Q12 : Donnez la liste des employés ayant une commission.
Type : Sélection IS NOT NULL
SELECT *
FROM EMP
WHERE COMM IS NOT NULL;
Pourquoi l'utilisation de cette solution ? En SQL, l'absence de valeur est représentée par NULL. On utilise WHERE COMM IS NOT NULL pour retenir uniquement les employés qui perçoivent une commission.
Ex2 - Q4 & Q13 : Donnez les noms, emplois et salaires des employés par emploi croissant, et pour chaque emploi, par salaire décroissant.
Type : Sélection + Tri ORDER BY
SELECT ENOM, PROF, SAL
FROM EMP
ORDER BY PROF ASC, SAL DESC;
Pourquoi l'utilisation de cette solution ? La clause ORDER BY PROF ASC, SAL DESC trie d'abord par profession de A à Z, puis départage les employés d'une même profession du salaire le plus élevé au plus bas.
Ex2 - Q5 & Q14 : Donnez le salaire moyen des employés.
Type : Agrégation AVG
SELECT AVG(SAL) AS salaire_moyen
FROM EMP;
Pourquoi l'utilisation de cette solution ? La fonction d'agrégation AVG(SAL) calcule directement la moyenne arithmétique de tous les salaires de la table EMP.
Ex2 - Q6 & Q16 : Donnez les numéros de département et leur salaire maximum.
Type : GROUP BY
SELECT DNO, MAX(SAL) AS sal_max
FROM EMP
GROUP BY DNO;
Pourquoi l'utilisation de cette solution ? On veut un résultat par département : on utilise GROUP BY DNO pour regrouper les employés de chaque département et MAX(SAL) pour extraire le salaire maximal de chaque groupe.
Ex2 - Q7 : Donner les noms des employés ayant le salaire maximum de chaque département.
Type : Sous-requête
SELECT ENOM, DNO, SAL
FROM EMP
WHERE (DNO, SAL) IN (
    SELECT DNO, MAX(SAL)
    FROM EMP
    GROUP BY DNO
);
Pourquoi l'utilisation de cette solution ? On utilise une sous-requête avec GROUP BY DNO qui retourne le couple (DNO, MAX(SAL)) de chaque département, puis la requête principale sélectionne les employés dont le couple (DNO, SAL) appartient à ce résultat.
Ex2 - Q8 & Q17 : Donnez les différentes professions et leur salaire moyen.
Type : GROUP BY
SELECT PROF, AVG(SAL) AS sal_moyen
FROM EMP
GROUP BY PROF;
Pourquoi l'utilisation de cette solution ? On regroupe les lignes par profession avec GROUP BY PROF et on applique AVG(SAL) sur chaque groupe.
Ex2 - Q9 : Donner les noms des employés du département COMMERCIAL embauchés le même jour qu'un employé du département PRODUCTION.
Type : JointureType : Sous-requête
SELECT EMP.ENOM
FROM EMP, DEPT
WHERE EMP.DNO = DEPT.DNO
  AND DEPT.DNOM = 'COMMERCIAL'
  AND EMP.DATEEMB IN (
      SELECT E2.DATEEMB
      FROM EMP E2, DEPT D2
      WHERE E2.DNO = D2.DNO
        AND D2.DNOM = 'PRODUCTION'
  );
Pourquoi l'utilisation de cette solution ? On combine une jointure (pour filtrer le département 'COMMERCIAL') et une sous-requête avec IN qui récupère l'ensemble des dates d'embauche des employés du département 'PRODUCTION'.
Ex2 - Q10 : Donner les noms des employés embauchés avant tous les employés du département 1.
Type : Sous-requête
SELECT ENOM
FROM EMP
WHERE DATEEMB < ALL (
    SELECT DATEEMB
    FROM EMP
    WHERE DNO = 1
);
Pourquoi l'utilisation de cette solution ? On utilise une sous-requête avec l'opérateur < ALL (ou < (SELECT MIN(DATEEMB) FROM EMP WHERE DNO = 1)) pour comparer la date d'embauche de chaque employé à toutes celles du département 1.
Ex2 - Q11 : Donner les noms des employés ayant le même emploi et le même directeur que 'Ali'.
Type : JointureType : Sous-requête
SELECT E.ENOM
FROM EMP E, DEPT D
WHERE E.DNO = D.DNO
  AND (E.PROF, D.DIR) = (
      SELECT E2.PROF, D2.DIR
      FROM EMP E2, DEPT D2
      WHERE E2.DNO = D2.DNO
        AND UPPER(E2.ENOM) = 'ALI'
  );
Pourquoi l'utilisation de cette solution ? L'emploi PROF est dans EMP et le directeur DIR est dans DEPT : la sous-requête joint les deux tables pour trouver le couple (PROF, DIR) d'Ali, et la requête principale affiche les employés partageant ce couple.
Ex2 - Q15 : Donner le nombre d'employés du département PRODUCTION.
Type : JointureType : Agrégation COUNT
SELECT COUNT(*) AS nb_employes
FROM EMP, DEPT
WHERE EMP.DNO = DEPT.DNO
  AND DEPT.DNOM = 'PRODUCTION';
Pourquoi l'utilisation de cette solution ? On utilise une jointure EMP.DNO = DEPT.DNO car le nom 'PRODUCTION' est dans DEPT tandis que les employés à compter sont dans EMP.
Ex2 - Q18 & Q19 : Donnez le ou les emplois ayant le salaire moyen le plus bas, ainsi que ce salaire moyen.
Type : GROUP BY + HAVINGType : Sous-requête
SELECT PROF, AVG(SAL) AS sal_moy_min
FROM EMP
GROUP BY PROF
HAVING AVG(SAL) <= ALL (
    SELECT AVG(SAL)
    FROM EMP
    GROUP BY PROF
);
Pourquoi l'utilisation de cette solution ? On regroupe par emploi (GROUP BY PROF) et on filtre les groupes avec HAVING AVG(SAL) <= ALL (...) face à une sous-requête calculant les moyennes de toutes les professions.
Ex2 - Q20 : Afficher la somme des commissions par mois d'embauche.
Type : DateType : GROUP BY
SELECT MONTH(DATEEMB) AS mois, SUM(COMM) AS total_comm
FROM EMP
GROUP BY MONTH(DATEEMB);
Pourquoi l'utilisation de cette solution ? La fonction de date MONTH(DATEEMB) extrait le numéro du mois, GROUP BY MONTH(DATEEMB) regroupe par mois et SUM(COMM) additionne les commissions.
Ex2 - Q21, Q22 & Q23 : Mises à jour (UPDATE) des salaires et des noms de villes.
Type : Mise à jour UPDATEType : Sous-requête
-- Q21 : Augmenter les salaires du département Développement de 10%
UPDATE EMP
SET SAL = SAL * 1.10
WHERE DNO = (SELECT DNO FROM DEPT WHERE UPPER(DNOM) = 'DEVELOPPEMENT');

-- Q22 : Augmenter les salaires des employés ayant une commission > 2000
UPDATE EMP
SET SAL = SAL * 1.10
WHERE COMM > 2000;

-- Q23 : Ajouter le préfixe 'TN' devant les villes des départements
UPDATE DEPT
SET VILLE = CONCAT('TN', VILLE);
Pourquoi l'utilisation de cette solution ? Pour Q21, la sous-requête récupère le DNO du département Développement afin de cibler UPDATE EMP. Pour Q23, la fonction CONCAT('TN', VILLE) préfixe chaque nom de ville.

V. Corrigé Exercices 3, 4 & 5 — Ventes, Tour de France & Notes

Ex3 - Q1, Q2 & Q3 : Gestion des Ventes (Chiffre d'affaires mensuel, taux de vente, produit le plus vendu).
Type : JointureType : GROUP BYType : Sous-requête
-- Q1 : Chiffre d'affaires mensuel de l'année en cours
SELECT MONTH(C.DateCmd) AS mois, SUM(V.Qte * P.PrixUnitaire) AS CA_mensuel
FROM Produit P, Vente V, Commande C
WHERE P.Ref = V.Ref
  AND V.Ncom = C.Ncom
  AND YEAR(C.DateCmd) = YEAR(NOW())
GROUP BY MONTH(C.DateCmd);

-- Q2 : Taux de vente de chaque produit
SELECT Ref, (SUM(Qte) * 100) / (SELECT SUM(Qte) FROM Vente) AS taux_vente
FROM Vente
GROUP BY Ref;

-- Q3 : Produit le plus vendu du mois en cours
SELECT P.Ref, P.Designation, SUM(V.Qte) AS total_vendu
FROM Produit P, Vente V
WHERE P.Ref = V.Ref
  AND MONTH(V.DateLiv) = MONTH(NOW())
  AND YEAR(V.DateLiv) = YEAR(NOW())
GROUP BY P.Ref, P.Designation
ORDER BY total_vendu DESC
LIMIT 1;
Pourquoi l'utilisation de cette solution ? On combine les jointures dans WHERE, les fonctions de date (YEAR(NOW()), MONTH(NOW())), le regroupement GROUP BY et une sous-requête scalaire (SELECT SUM(Qte) FROM Vente) pour rapporter la quantité de chaque produit au total global.
Ex4 - Q1 à Q7 : Tour de France 2021 (Jointures, Sous-requête NOT IN, GROUP BY / HAVING).

-- Q1 : Composition de l'équipe FESTINA
SELECT B.NumeroCoureur, B.NomCoureur, C.NomPays
FROM EQUIPE A, COUREUR B, PAYS C
WHERE A.CodeEquipe = B.CodeEquipe

-- Q2 : Nombre de kilomètres total du Tour de France 2021
SELECT SUM(NbKm) AS total_km FROM ETAPE;

-- Q3 : Nombre de km total des étapes de type 'HAUTE MONTAGNE'
SELECT SUM(A.NbKm) AS km_haute_montagne
FROM ETAPE A, TYPE_ETAPE B
WHERE A.CodeType = B.CodeType
  AND B.LibelleType = 'HAUTE MONTAGNE';

-- Q4 : Noms des coureurs qui n'ont pas obtenu de bonifications
SELECT NomCoureur
FROM COUREUR
WHERE NumeroCoureur NOT IN (SELECT NumeroCoureur FROM ATTRIBUER_BONIFICATION);

-- Q5 : Noms des coureurs ayant participé à toutes les étapes
SELECT B.NomCoureur
FROM PARTICIPER A, COUREUR B
WHERE A.NumeroCoureur = B.NumeroCoureur
GROUP BY B.NumeroCoureur, B.NomCoureur
HAVING COUNT(*) = (SELECT COUNT(*) FROM ETAPE);

-- Q6 : Classement général des coureurs à l'issue des 13 premières étapes
SELECT B.NomCoureur, B.CodeEquipe, B.CodePays, SUM(A.TempsRealise) AS Total
FROM PARTICIPER A, COUREUR B
WHERE A.NumeroCoureur = B.NumeroCoureur
  AND A.NumeroEtape <= 13
GROUP BY B.NumeroCoureur, B.NomCoureur, B.CodeEquipe, B.CodePays
ORDER BY Total ASC;

-- Q7 : Classement par équipe à l'issue des 13 premières étapes
SELECT C.NomEquipe, SUM(A.TempsRealise) AS Total
FROM PARTICIPER A, COUREUR B, EQUIPE C
WHERE A.NumeroCoureur = B.NumeroCoureur
  AND B.CodeEquipe = C.CodeEquipe
  AND A.NumeroEtape <= 13
GROUP BY C.CodeEquipe, C.NomEquipe
ORDER BY Total ASC;
Pourquoi l'utilisation de cette solution ? Q4 utilise une sous-requête avec NOT IN pour exprimer l'exclusion (« n'ont pas obtenu »). Q5 utilise GROUP BY + HAVING COUNT(*) = (SELECT COUNT(*) FROM ETAPE) pour vérifier la participation à toutes les étapes.
Ex5 - Q1 à Q7 : Gestion des Notes Annuelles (Agrégation, Jointures, Vues et Sous-requêtes).
Type : JointureType : GROUP BYType : Sous-requête
-- Q1 : Nombre total d'étudiants
SELECT COUNT(*) AS nb_etudiants FROM ETUDIANT;

-- Q2 : Note la plus haute et note la plus basse
SELECT MIN(Note) AS plus_basse_note, MAX(Note) AS plus_haute_note FROM EVALUER;

-- Q3 : Moyennes de chaque étudiant dans chacune des matières (Vue MOYETUMAT)
CREATE VIEW MOYETUMAT AS
SELECT E.NEtudiant, E.Nom, E.Prenom, M.CodeMat, M.LibelleMat, M.CoeffMat, AVG(EV.Note) AS MoyEtuMat
FROM ETUDIANT E, MATIERE M, EVALUER EV
WHERE E.NEtudiant = EV.NEtudiant
  AND EV.CodeMat = M.CodeMat
GROUP BY E.NEtudiant, E.Nom, E.Prenom, M.CodeMat, M.LibelleMat, M.CoeffMat;

-- Q4 : Moyennes par matière à partir de la vue MOYETUMAT
SELECT LibelleMat, AVG(MoyEtuMat) AS moy_matiere
FROM MOYETUMAT
GROUP BY LibelleMat;

-- Q5 : Moyenne générale pondérée de chaque étudiant (Vue MGETU)
CREATE VIEW MGETU AS
SELECT NEtudiant, Nom, Prenom, SUM(MoyEtuMat * CoeffMat) / SUM(CoeffMat) AS MgEtu
FROM MOYETUMAT
GROUP BY NEtudiant, Nom, Prenom;

-- Q6 : Moyenne générale de la promotion
SELECT AVG(MgEtu) AS moy_promotion FROM MGETU;

-- Q7 : Étudiants ayant une moyenne >= moyenne générale de la promotion
SELECT NEtudiant, Nom, Prenom, MgEtu
FROM MGETU
WHERE MgEtu >= (SELECT AVG(MgEtu) FROM MGETU);
Pourquoi l'utilisation de cette solution ? Les vues MOYETUMAT et MGETU décomposent le calcul des moyennes par matière puis des moyennes générales pondérées, et Q7 utilise une sous-requête pour comparer chaque étudiant à la moyenne de la promotion.
