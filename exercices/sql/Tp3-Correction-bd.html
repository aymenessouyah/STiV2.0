I. Création de la base de données « bdtp5 » et des tables (CREATE DATABASE / CREATE TABLE)

CREATE DATABASE bdtp5;
USE bdtp5;

CREATE TABLE Sondage (
    NumS INT AUTO_INCREMENT PRIMARY KEY,
    Theme VARCHAR(50) NOT NULL,
    DateDebut DATE NOT NULL
);

CREATE TABLE Question (
    NumQ INT,
    NumS INT,
    Contenu VARCHAR(150) NOT NULL,
    PRIMARY KEY (NumQ, NumS),
    FOREIGN KEY (NumS) REFERENCES Sondage(NumS)
);

CREATE TABLE Participant (
    IdParticipant INT AUTO_INCREMENT PRIMARY KEY,
    Mail VARCHAR(50) NOT NULL,
    Mdp VARCHAR(6) NOT NULL,
    Genre CHAR(1) CHECK (Genre IN ('M', 'F'))
);

CREATE TABLE Reponse (
    NumQ INT,
    NumS INT,
    IdParticipant INT,
    Rep CHAR(1) CHECK (Rep IN ('O', 'N', 'S')),
    PRIMARY KEY (NumQ, NumS, IdParticipant),
    FOREIGN KEY (NumQ, NumS) REFERENCES Question(NumQ, NumS),
    FOREIGN KEY (IdParticipant) REFERENCES Participant(IdParticipant)
);

Ex1 - Q3 : Afficher les adresses mail et les mots de passe existant dans la base de données.
Type : Projection simple
SELECT Mail, Mdp
FROM Participant;
Pourquoi l'utilisation de cette solution ? Les deux colonnes demandées (Mail et Mdp) appartiennent uniquement à la table Participant : une projection simple sans condition suffit.
Ex1 - Q4 : Afficher le nombre total des participants qui ont participé à un sondage relatif à un thème.
Type : JointureType : GROUP BY
SELECT S.Theme, COUNT(DISTINCT R.IdParticipant) AS nb_participants
FROM Sondage S, Reponse R
WHERE S.NumS = R.NumS
GROUP BY S.NumS, S.Theme;
Pourquoi l'utilisation de cette solution ? On relie Sondage et Reponse par la jointure S.NumS = R.NumS, on regroupe par thème avec GROUP BY et on utilise COUNT(DISTINCT R.IdParticipant) pour ne compter chaque participant qu'une seule fois par sondage.
Ex1 - Q5 : Afficher le nombre total des femmes qui ont participé à un sondage relatif à un thème.
Type : JointureType : GROUP BY
SELECT S.Theme, COUNT(DISTINCT P.IdParticipant) AS nb_femmes
FROM Sondage S, Reponse R, Participant P
WHERE S.NumS = R.NumS
  AND R.IdParticipant = P.IdParticipant
  AND P.Genre = 'F'
GROUP BY S.NumS, S.Theme;
Pourquoi l'utilisation de cette solution ? Le thème est dans Sondage, la participation dans Reponse et le genre dans Participant : on réalise une jointure à 3 tables dans WHERE avec le filtre P.Genre = 'F' et un GROUP BY par thème.
Ex1 - Q6 : Afficher le nombre total des hommes qui ont participé à un sondage relatif à un thème.
Type : JointureType : GROUP BY
SELECT S.Theme, COUNT(DISTINCT P.IdParticipant) AS nb_hommes
FROM Sondage S, Reponse R, Participant P
WHERE S.NumS = R.NumS
  AND R.IdParticipant = P.IdParticipant
  AND P.Genre = 'M'
GROUP BY S.NumS, S.Theme;
Pourquoi l'utilisation de cette solution ? Même principe que la question 5 : jointure entre les 3 tables dans WHERE, filtrage sur le genre masculin P.Genre = 'M' et regroupement GROUP BY S.NumS, S.Theme.
Ex1 - Q7 : Afficher le pourcentage des internautes ayant répondu « Oui » relatif à un thème.
Type : JointureType : GROUP BYType : Requête imbriquée
SELECT S.Theme,
       (COUNT(*) * 100) / (SELECT COUNT(*) FROM Reponse R2 WHERE R2.NumS = S.NumS) AS pct_oui
FROM Sondage S, Reponse R
WHERE S.NumS = R.NumS
  AND R.Rep = 'O'
GROUP BY S.NumS, S.Theme;
Pourquoi l'utilisation de cette solution ? On filtre les réponses « Oui » (R.Rep = 'O'), on regroupe par thème (GROUP BY) et on divise COUNT(*) * 100 par une requête imbriquée comptant le total des réponses de ce sondage.
Ex1 - Q8 : Afficher le pourcentage des internautes ayant répondu « Non » pour chaque thème.
Type : JointureType : GROUP BYType : Requête imbriquée
SELECT S.Theme,
       (COUNT(*) * 100) / (SELECT COUNT(*) FROM Reponse R2 WHERE R2.NumS = S.NumS) AS pct_non
FROM Sondage S, Reponse R
WHERE S.NumS = R.NumS
  AND R.Rep = 'N'
GROUP BY S.NumS, S.Theme;
Pourquoi l'utilisation de cette solution ? On applique la même combinaison (jointure + GROUP BY + requête imbriquée au dénominateur) en filtrant cette fois sur R.Rep = 'N'.
Ex1 - Q9 : Afficher le pourcentage des internautes ayant répondu « Sans avis » pour chaque thème.
Type : JointureType : GROUP BYType : Requête imbriquée
SELECT S.Theme,
       (COUNT(*) * 100) / (SELECT COUNT(*) FROM Reponse R2 WHERE R2.NumS = S.NumS) AS pct_sans_avis
FROM Sondage S, Reponse R
WHERE S.NumS = R.NumS
  AND R.Rep = 'S'
GROUP BY S.NumS, S.Theme;
Pourquoi l'utilisation de cette solution ? On filtre sur les réponses « Sans avis » (R.Rep = 'S') et on rapporte le nombre de réponses de chaque groupe au total du sondage via la requête imbriquée.

IV. Corrigé Exercice 2 — Départements & Employés (Questions 1 à 7)

Ex2 - Q1 : Donnez la liste des employés ayant une commission ?
Type : Sélection IS NOT NULL
SELECT *
FROM Employes
WHERE COMM IS NOT NULL;
Pourquoi l'utilisation de cette solution ? On teste la présence d'une commission avec l'opérateur SQL dédié IS NOT NULL dans la clause WHERE.
Ex2 - Q2 : Donnez les noms, emplois et salaires des employés par emploi croissant, et pour chaque emploi, par salaire décroissant ?
Type : Sélection + Tri ORDER BY
SELECT ENOM, PROF, SAL
FROM Employes
ORDER BY PROF ASC, SAL DESC;
Pourquoi l'utilisation de cette solution ? On trie d'abord sur PROF ASC (ordre alphabétique croissant), puis sur SAL DESC (ordre décroissant des salaires).
Ex2 - Q3 : Donnez le salaire moyen des employés ?
Type : Agrégation AVG
SELECT AVG(SAL) AS salaire_moyen
FROM Employes;
Pourquoi l'utilisation de cette solution ? La fonction d'agrégation AVG(SAL) calcule la moyenne de la colonne SAL sur toute la table Employes.
Ex2 - Q4 : Donnez le salaire moyen du département Production ?
Type : JointureType : Agrégation AVG
SELECT AVG(E.SAL) AS sal_moy_production
FROM Employes E, Departements D
WHERE E.DNO = D.DNO
  AND UPPER(D.DNOM) = 'PRODUCTION';
Pourquoi l'utilisation de cette solution ? Le salaire est dans Employes et le nom du département dans Departements : il faut une jointure E.DNO = D.DNO dans WHERE avant de calculer AVG(E.SAL).
Ex2 - Q5 : Donnez les numéros de département et leur salaire maximum ?
Type : GROUP BY
SELECT DNO, MAX(SAL) AS sal_max
FROM Employes
GROUP BY DNO;
Pourquoi l'utilisation de cette solution ? On regroupe les employés par numéro de département (GROUP BY DNO) afin que MAX(SAL) retourne le salaire maximal de chaque département.
Ex2 - Q6 : Donnez les différentes professions et leur salaire moyen ?
Type : GROUP BY
SELECT PROF, AVG(SAL) AS sal_moy
FROM Employes
GROUP BY PROF;
Pourquoi l'utilisation de cette solution ? On utilise GROUP BY PROF pour former un groupe par profession et calculer la moyenne des salaires AVG(SAL) de chacune.
Ex2 - Q7 : Donnez le salaire moyen par profession le plus bas ?
Type : GROUP BYType : Sous-requête
SELECT PROF, AVG(SAL) AS sal_moy_min
FROM Employes
GROUP BY PROF
HAVING AVG(SAL) <= ALL (
    SELECT AVG(SAL)
    FROM Employes
    GROUP BY PROF
);
Pourquoi l'utilisation de cette solution ? On calcule le salaire moyen par profession avec GROUP BY PROF et on utilise HAVING AVG(SAL) <= ALL (...) (ou ORDER BY sal_moy_min ASC LIMIT 1) pour retenir la profession ayant la moyenne la plus basse.

V. Corrigé Exercice 3 — Gestion des Notes Annuelles (Questions 1 à 5)

Ex3 - Q1 : Afficher le nombre total d'étudiants ?
Type : Agrégation COUNT
SELECT COUNT(*) AS nb_etudiants
FROM ETUDIANT;
Pourquoi l'utilisation de cette solution ? On compte le nombre total de lignes de la table ETUDIANT à l'aide de COUNT(*).
Ex3 - Q2 : Afficher la note la plus haute et la note la plus basse pour chaque étudiant ?
Type : GROUP BY
SELECT NEtudiant, MAX(Note) AS note_max, MIN(Note) AS note_min
FROM EVALUER
GROUP BY NEtudiant;
Pourquoi l'utilisation de cette solution ? L'expression « pour chaque étudiant » impose un regroupement GROUP BY NEtudiant sur la table EVALUER avec les fonctions MAX(Note) et MIN(Note).
Ex3 - Q3 : Afficher les moyennes de chaque étudiant dans chacune des matières ?
Type : JointureType : GROUP BY
SELECT E.NEtudiant, E.Nom, E.Prenom, M.LibelleMat, AVG(EV.Note) AS moyenne
FROM ETUDIANT E, MATIERE M, EVALUER EV
WHERE E.NEtudiant = EV.NEtudiant
  AND M.CodeMat = EV.CodeMat
GROUP BY E.NEtudiant, E.Nom, E.Prenom, M.CodeMat, M.LibelleMat;
Pourquoi l'utilisation de cette solution ? On combine une jointure à 3 tables (ETUDIANT, MATIERE, EVALUER) dans WHERE et un regroupement GROUP BY sur le couple (étudiant, matière) pour calculer AVG(EV.Note).
Ex3 - Q4 : Afficher les noms et les prénoms des étudiants dans chaque matière ?
Type : Jointure
SELECT DISTINCT M.LibelleMat, E.Nom, E.Prenom
FROM ETUDIANT E, MATIERE M, EVALUER EV
WHERE E.NEtudiant = EV.NEtudiant
  AND M.CodeMat = EV.CodeMat
ORDER BY M.LibelleMat ASC, E.Nom ASC;
Pourquoi l'utilisation de cette solution ? On effectue une jointure entre les 3 tables via la table de liaison EVALUER, avec DISTINCT pour éviter qu'un étudiant évalué plusieurs fois dans la même matière n'apparaisse en double.
Ex3 - Q5 : Afficher les noms et les prénoms des étudiants dans un ordre décroissant des notes pour chaque matière ?
Type : JointureType : Tri ORDER BY
SELECT M.LibelleMat, E.Nom, E.Prenom, EV.Note
FROM ETUDIANT E, MATIERE M, EVALUER EV
WHERE E.NEtudiant = EV.NEtudiant
  AND M.CodeMat = EV.CodeMat
ORDER BY M.LibelleMat ASC, EV.Note DESC;
Pourquoi l'utilisation de cette solution ? Après la jointure des 3 tables dans WHERE, on trie par matière (M.LibelleMat ASC) puis par note décroissante (EV.Note DESC).
