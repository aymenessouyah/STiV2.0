Corrigé Série 4 — Jointures, Sous-requêtes et Group By

Schéma relationnel de la base de données ETUDIANT_BD :
• SEXE (Cdsexe, Lbsexe)
• ENSEIGNANT (Numens, Nomens, Grade, Ancien)
• ETUDIANT (Numetu, Nometu, Dtnaiss, #Cdsexe)
• MATIERE (Numat, Nomat, Coeff, #Numens)
• NOTES (#Numetu, #Numat, Note)

I. Création de la Base de Données et des 5 Tables (LDD)

On crée d'abord les tables parentes sans clé étrangère (SEXE et ENSEIGNANT), puis les tables enfants (ETUDIANT et MATIERE), et enfin la table d'association NOTES munie d'une clé primaire composée : 

CREATE DATABASE ETUDIANT_BD;
USE ETUDIANT_BD;

CREATE TABLE SEXE (
  Cdsexe CHAR(1) PRIMARY KEY,
  Lbsexe VARCHAR(20) NOT NULL
);

CREATE TABLE ENSEIGNANT (
  Numens INT PRIMARY KEY,
  Nomens VARCHAR(50) NOT NULL,
  Grade  VARCHAR(30) NOT NULL,
  Ancien INT NOT NULL
);

CREATE TABLE ETUDIANT (
  Numetu  INT PRIMARY KEY,
  Nometu  VARCHAR(50) NOT NULL,
  Dtnaiss DATE NOT NULL,
  Cdsexe  CHAR(1) NOT NULL,
  FOREIGN KEY (Cdsexe) REFERENCES SEXE(Cdsexe)
);

CREATE TABLE MATIERE (
  Numat  INT PRIMARY KEY,
  Nomat  VARCHAR(40) NOT NULL,
  Coeff  INT NOT NULL,
  Numens INT NOT NULL,
  FOREIGN KEY (Numens) REFERENCES ENSEIGNANT(Numens)
);

CREATE TABLE NOTES (
  Numetu INT NOT NULL,
  Numat  INT NOT NULL,
  Note   DECIMAL(4,2) NOT NULL,
  PRIMARY KEY (Numetu, Numat),
  FOREIGN KEY (Numetu) REFERENCES ETUDIANT(Numetu),
  FOREIGN KEY (Numat)  REFERENCES MATIERE(Numat)
);
Pourquoi cet ordre de création ? En SQL, une clé étrangère (FOREIGN KEY) ne peut référencer qu'une table déjà existante : on crée donc SEXE et ENSEIGNANT avant ETUDIANT et MATIERE, puis NOTES en dernier.

II. Insertion des éléments dans la Base de Données (LMD : INSERT INTO)

En respectant l'intégrité référentielle, on insère les enregistrements dans les tables mères puis dans les tables filles : 

-- 1. Insertion dans SEXE
INSERT INTO SEXE VALUES ('H', 'Garçon');
INSERT INTO SEXE VALUES ('F', 'Fille');

-- 2. Insertion dans ENSEIGNANT
INSERT INTO ENSEIGNANT VALUES (101, 'Ali Ben Salah',  'Professeur', 15);

INSERT INTO ENSEIGNANT VALUES (103, 'Karim Foughali', 'Assistant',   3);

-- 3. Insertion dans ETUDIANT
INSERT INTO ETUDIANT VALUES (1, 'Asma Ben Mahmoud', '2003-05-12', 'F');
INSERT INTO ETUDIANT VALUES (2, 'Bassem Hdhili',    '2004-11-23', 'H');

-- 4. Insertion dans MATIERE
INSERT INTO MATIERE VALUES (10, 'Informatique',  3, 101);

INSERT INTO NOTES VALUES (1, 10, 15.50), (1, 11, 12.00), (1, 12, 14.00);

Pourquoi cet ordre d'insertion ? Chaque valeur de clé étrangère (comme Cdsexe = 'F', Numens = 101 ou Numat = 10) doit préexister comme clé primaire dans sa table de référence avant d'être utilisée dans ETUDIANT, MATIERE ou NOTES.

III. Corrigé détaillé des 15 Requêtes (Type & Justification de la solution)

Requête 1 : Afficher quel était l'âge moyen des garçons et des filles au 1er janvier 2025.
Type : Jointure + GROUP BY / Agrégation (AVG) 
SELECT S.Lbsexe, AVG(DATEDIFF('2025-01-01', E.Dtnaiss) / 365) AS "Age Moyen"
FROM SEXE S, ETUDIANT E
WHERE E.Cdsexe = S.Cdsexe
GROUP BY S.Cdsexe, S.Lbsexe;
Pourquoi l'utilisation de cette solution ? Le libellé du sexe (Lbsexe) est dans la table SEXE tandis que la date de naissance (Dtnaiss) est dans ETUDIANT : il faut donc une jointure WHERE E.Cdsexe = S.Cdsexe. Ensuite, comme la moyenne est demandée pour chaque sexe (garçons d'un côté, filles de l'autre), on utilise GROUP BY S.Cdsexe, S.Lbsexe avec la fonction d'agrégation AVG(...).
Requête 2 : Afficher le nom et le grade des enseignants d'histoire.
Type : Jointure 
SELECT E.Nomens, E.Grade
FROM ENSEIGNANT E, MATIERE M
WHERE E.Numens = M.Numens
  AND M.Nomat = 'Histoire';
Pourquoi l'utilisation de cette solution ? Les colonnes à afficher (Nomens, Grade) appartiennent à ENSEIGNANT, mais la condition porte sur le nom de la matière (Nomat = 'Histoire') situé dans MATIERE. Une jointure WHERE E.Numens = M.Numens permet de relier chaque matière à son enseignant sur la même ligne et d'afficher ses attributs.
Requête 3 : Afficher les noms et numéro des étudiants qui n'ont pas de notes en Sociologie.
Type : Sous-requête (NOT IN) Requête imbriquée 
SELECT E.Nometu, E.Numetu
FROM ETUDIANT E
WHERE E.Numetu NOT IN (
  SELECT N.Numetu
  FROM NOTES N, MATIERE M
  WHERE N.Numat = M.Numat
    AND M.Nomat = 'Sociologie'
);
Pourquoi l'utilisation de cette solution ? On cherche une absence d'enregistrement dans NOTES pour la matière 'Sociologie'. Une simple jointure avec M.Nomat != 'Sociologie' serait fausse car elle garderait tout étudiant ayant une note en Informatique même s'il a aussi une note en Sociologie. On utilise donc une sous-requête imbriquée qui trouve d'abord ceux qui ont une note en Sociologie, puis NOT IN pour les exclure.
Requête 4 : Afficher le nom et le coefficient des matières enseignées par des maîtres de conférences ou des assistants.
Type : Jointure 
SELECT M.Nomat, M.Coeff
FROM MATIERE M, ENSEIGNANT E
WHERE M.Numens = E.Numens
  AND E.Grade IN ('MCF', 'Assistant');
Pourquoi l'utilisation de cette solution ? Le nom et le coefficient sont dans MATIERE alors que le grade ('MCF' ou 'Assistant') est dans ENSEIGNANT. La jointure WHERE M.Numens = E.Numens relie directement chaque matière à son enseignant, et l'opérateur IN ('MCF', 'Assistant') filtre les deux grades souhaités sans avoir besoin de sous-requête.
Requête 5 : Afficher pour chaque étudiant (nom et numéro), et par ordre alphabétique, la moyenne obtenue dans chaque matière.
Type : Jointure (3 tables) + GROUP BY & ORDER BY 
SELECT E.Nometu, E.Numetu, M.Nomat, AVG(N.Note) AS Moyenne
FROM ETUDIANT E, NOTES N, MATIERE M
WHERE E.Numetu = N.Numetu
  AND N.Numat = M.Numat
GROUP BY E.Numetu, E.Nometu, M.Numat, M.Nomat
ORDER BY E.Nometu ASC;
Pourquoi l'utilisation de cette solution ? On doit afficher simultanément des colonnes issues de 3 tables (ETUDIANT, MATIERE, NOTES), ce qui impose une double jointure (E.Numetu = N.Numetu AND N.Numat = M.Numat). Comme la moyenne AVG(N.Note) est demandée par étudiant et par matière, on utilise GROUP BY E.Numetu, E.Nometu, M.Numat, M.Nomat suivi de ORDER BY E.Nometu ASC.
Requête 6 : Afficher le nom, l'âge et le sexe des étudiants ayant une note d'informatique supérieure à la moyenne générale de la classe.
Type : Jointure + Sous-requête imbriquée scalaire 
SELECT E.Nometu, DATEDIFF(CURRENT_DATE, E.Dtnaiss) / 365 AS Age, S.Lbsexe
FROM ETUDIANT E, SEXE S, NOTES N, MATIERE M
WHERE E.Cdsexe = S.Cdsexe
  AND E.Numetu = N.Numetu
  AND N.Numat = M.Numat
  AND M.Nomat = 'Informatique'
  AND N.Note > (
    SELECT AVG(N2.Note)
    FROM NOTES N2, MATIERE M2
    WHERE N2.Numat = M2.Numat
      AND M2.Nomat = 'Informatique'
  );
Pourquoi l'utilisation de cette solution ? En SQL, il est interdit d'écrire WHERE N.Note > AVG(N.Note). Il faut donc obligatoirement une sous-requête imbriquée qui calcule d'abord la moyenne de la classe, puis la requête principale utilise une jointure sur ETUDIANT, SEXE, NOTES et MATIERE pour garder les étudiants dont la note dépasse cette moyenne.
Requête 7 : Afficher, pour chaque étudiant ayant une note dans chacune des matières, la moyenne obtenue au diplôme.
Type : Jointure + GROUP BY / HAVING + Sous-requête imbriquée 
SELECT E.Nometu, E.Numetu, SUM(N.Note * M.Coeff) / SUM(M.Coeff) AS Moyenne
FROM ETUDIANT E, NOTES N, MATIERE M
WHERE E.Numetu = N.Numetu
  AND N.Numat = M.Numat
GROUP BY E.Numetu, E.Nometu
HAVING COUNT(DISTINCT N.Numat) = (SELECT COUNT(*) FROM MATIERE)
ORDER BY E.Nometu ASC;
Pourquoi l'utilisation de cette solution ? Le calcul de la moyenne pondérée par étudiant nécessite une jointure entre ETUDIANT, NOTES et MATIERE et un GROUP BY E.Numetu, E.Nometu. Pour vérifier que l'étudiant a été noté dans toutes les matières, on filtre chaque groupe avec HAVING COUNT(DISTINCT N.Numat) comparé à la sous-requête (SELECT COUNT(*) FROM MATIERE) qui donne le nombre total de matières.
Requête 8 : Afficher le nom, le grade et l'ancienneté des enseignants qui enseignent dans plus d'une matière.
Type : Jointure + GROUP BY / HAVING 
SELECT E.Nomens, E.Grade, E.Ancien
FROM ENSEIGNANT E, MATIERE M
WHERE E.Numens = M.Numens
GROUP BY E.Numens, E.Nomens, E.Grade, E.Ancien
HAVING COUNT(M.Numat) > 1;
Pourquoi l'utilisation de cette solution ? On relie chaque enseignant à ses matières par la jointure WHERE E.Numens = M.Numens, puis on regroupe par enseignant avec GROUP BY. Comme la condition « plus d'une matière » porte sur la fonction d'agrégation COUNT(M.Numat) > 1, elle doit obligatoirement être placée dans la clause HAVING.
Requête 9 : Afficher le nombre de garçons et le nombre de filles qui ont réussi au diplôme (moyenne >= 10).
Type : Requête imbriquée (IN + GROUP BY / HAVING) + Jointure & GROUP BY 
SELECT S.Lbsexe, COUNT(E.Numetu) AS Nb_Reussis
FROM SEXE S, ETUDIANT E
WHERE S.Cdsexe = E.Cdsexe
  AND E.Numetu IN (
    SELECT N.Numetu
    FROM NOTES N, MATIERE M
    WHERE N.Numat = M.Numat
    GROUP BY N.Numetu
    HAVING SUM(N.Note * M.Coeff) / SUM(M.Coeff) >= 10
       AND COUNT(DISTINCT N.Numat) = (SELECT COUNT(*) FROM MATIERE)
  )
GROUP BY S.Cdsexe, S.Lbsexe;
Pourquoi l'utilisation de cette solution ? Il y a ici deux regroupements différents : il faut d'abord regrouper par étudiant pour calculer sa moyenne au diplôme (>= 10), puis regrouper par sexe pour compter le nombre d'admis. On utilise donc une requête imbriquée (avec IN) qui identifie les Numetu ayant réussi, et la requête externe fait la jointure avec SEXE et le GROUP BY S.Cdsexe, S.Lbsexe.
Requête 10 : Afficher le nom, le numéro et le sexe des étudiants ayant une note en Informatique supérieure à leur note de Mathématiques.
Type : Jointure + Sous-requête corrélée (Requête imbriquée) 
SELECT E.Nometu, E.Numetu, S.Lbsexe
FROM ETUDIANT E, SEXE S, NOTES N1, MATIERE M1
WHERE E.Cdsexe = S.Cdsexe
  AND E.Numetu = N1.Numetu
  AND N1.Numat = M1.Numat
  AND M1.Nomat = 'Informatique'
  AND N1.Note > (
    SELECT N2.Note
    FROM NOTES N2, MATIERE M2
    WHERE N2.Numat = M2.Numat
      AND M2.Nomat = 'Mathématiques'
      AND N2.Numetu = E.Numetu
  );
Pourquoi l'utilisation de cette solution ? On compare deux notes appartenant au même étudiant mais stockées sur deux lignes distinctes de la table NOTES. La requête principale récupère par jointure la note d'Informatique (N1.Note) de l'étudiant E.Numetu, et la sous-requête corrélée (reliée par N2.Numetu = E.Numetu) récupère sa note de Mathématiques pour effectuer la comparaison N1.Note > (...).
Requête 11 : Afficher le nom des couples (garçon, fille) dont la différence d'âge ne dépasse pas 6 mois (180 jours).
Type : Auto-jointure (Jointure d'une table avec elle-même) 
SELECT E1.Nometu AS Nom_Garcon, E2.Nometu AS Nom_Fille
FROM ETUDIANT E1, ETUDIANT E2
WHERE E1.Cdsexe = 'H'
  AND E2.Cdsexe = 'F'
  AND ABS(DATEDIFF(E1.Dtnaiss, E2.Dtnaiss)) <= 180;
Pourquoi l'utilisation de cette solution ? Les garçons et les filles se trouvent tous dans la même table ETUDIANT. Pour comparer sur une même ligne la date de naissance d'un garçon et celle d'une fille, on utilise une auto-jointure en appelant deux fois la table avec deux alias différents (ETUDIANT E1, ETUDIANT E2).
Requête 12 : Pour les étudiants n'ayant pas de note dans une matière, afficher le numéro, le nom de l'étudiant et le nom de la matière concernée.
Type : Sous-requête corrélée (NOT IN) Requête imbriquée 
SELECT E.Numetu, E.Nometu, M.Nomat
FROM ETUDIANT E, MATIERE M
WHERE E.Numetu NOT IN (
  SELECT N.Numetu
  FROM NOTES N
  WHERE N.Numat = M.Numat
);
Pourquoi l'utilisation de cette solution ? Une jointure avec la table NOTES ne peut jamais afficher une matière où l'étudiant n'a aucune ligne dans NOTES. On génère donc tous les couples possibles (ETUDIANT E, MATIERE M) dans le FROM, puis la sous-requête corrélée avec NOT IN conserve uniquement les couples (étudiant, matière) absents de la table NOTES.
Requête 13 : Afficher les matières pour lesquelles la moyenne des notes est inférieure à 10, avec le nom de l'enseignant correspondant.
Type : Jointure (3 tables) + GROUP BY / HAVING 
SELECT M.Nomat, E.Nomens, AVG(N.Note) AS Moyenne
FROM ENSEIGNANT E, MATIERE M, NOTES N
WHERE E.Numens = M.Numens
  AND M.Numat = N.Numat
GROUP BY M.Numat, M.Nomat, E.Numens, E.Nomens
HAVING AVG(N.Note) < 10;
Pourquoi l'utilisation de cette solution ? Il faut relier la matière (MATIERE), son enseignant (ENSEIGNANT) et les notes obtenues (NOTES) grâce à une double jointure. Ensuite, comme la condition AVG(N.Note) < 10 porte sur la moyenne calculée par matière, on utilise GROUP BY suivi du filtre de groupe HAVING AVG(N.Note) < 10.
Requête 14 : Afficher, pour chaque matière, quelle est la meilleure note et quel est l'étudiant qui l'a obtenue.
Type : Jointure + Sous-requête corrélée (= SELECT MAX) 
SELECT M.Nomat, N.Note AS Meilleure_Note, E.Nometu
FROM MATIERE M, NOTES N, ETUDIANT E
WHERE N.Numat = M.Numat
  AND E.Numetu = N.Numetu
  AND N.Note = (
    SELECT MAX(N2.Note)
    FROM NOTES N2
    WHERE N2.Numat = M.Numat
  );
Pourquoi l'utilisation de cette solution ? Un simple GROUP BY M.Numat avec MAX(N.Note) donnerait la meilleure note de chaque matière mais ne permettrait pas de savoir quel étudiant (E.Nometu) a obtenu cette note maximale. On utilise donc une jointure entre MATIERE, NOTES et ETUDIANT, combinée à une sous-requête corrélée N.Note = (SELECT MAX(N2.Note) ... WHERE N2.Numat = M.Numat).
Requête 15 : Afficher, pour chaque sexe (Homme, Femme), la moyenne des notes dans la matière enseignée par Ali Ben Salah.
Type : Jointure (5 tables) + GROUP BY / Agrégation (AVG) 
SELECT S.Lbsexe, AVG(N.Note) AS Moyenne
FROM SEXE S, ETUDIANT E, NOTES N, MATIERE M, ENSEIGNANT G
WHERE S.Cdsexe = E.Cdsexe
  AND E.Numetu = N.Numetu
  AND N.Numat = M.Numat
  AND M.Numens = G.Numens
  AND UPPER(G.Nomens) = 'ALI BEN SALAH'
GROUP BY S.Cdsexe, S.Lbsexe;
Pourquoi l'utilisation de cette solution ? Le chemin entre le libellé du sexe (SEXE), l'étudiant (ETUDIANT), ses notes (NOTES), la matière (MATIERE) et le nom de l'enseignant (ENSEIGNANT) traverse les 5 tables : on écrit donc 4 conditions de jointure dans le WHERE avec le filtre sur 'ALI BEN SALAH', puis on regroupe par sexe avec GROUP BY S.Cdsexe, S.Lbsexe pour calculer AVG(N.Note).
