Corrigé Série 6 : Récapitulatif LDD + LMD (Base ÉTUDIANT)

I. Création de la base de données « Gestion_Etudiant » et des 5 tables (LDD)

CREATE DATABASE Gestion_Etudiant;
USE Gestion_Etudiant;

CREATE TABLE SEXE (
    Cdsexe CHAR(1) PRIMARY KEY,
    Lbsexe VARCHAR(20) NOT NULL
);

CREATE TABLE ETUDIANT (
    Numetu INT PRIMARY KEY,
    Nometu VARCHAR(50) NOT NULL,
    Dtnaiss DATE NOT NULL,
    Cdsexe CHAR(1) NOT NULL,
    FOREIGN KEY (Cdsexe) REFERENCES SEXE(Cdsexe)
);

CREATE TABLE ENSEIGNANT (
    Numens INT PRIMARY KEY,
    Nomens VARCHAR(50) NOT NULL,
    Grade VARCHAR(30) NOT NULL,
    Ancien INT
);

CREATE TABLE MATIERE (
    Numat INT PRIMARY KEY,
    Nomat VARCHAR(50) NOT NULL,
    Coeff INT NOT NULL,
    Numens INT NOT NULL,
    CONSTRAINT fk_matiere_enseignant FOREIGN KEY (Numens) REFERENCES ENSEIGNANT(Numens)
);

CREATE TABLE NOTES (
    Numetu INT,
    Numat INT,
    Note DECIMAL(5,2) CHECK (Note BETWEEN 0 AND 20),
    PRIMARY KEY (Numetu, Numat),
    FOREIGN KEY (Numetu) REFERENCES ETUDIANT(Numetu),
    FOREIGN KEY (Numat) REFERENCES MATIERE(Numat)
);

III. Corrigé Partie I — QCM, Commandes LDD & Vrai/Faux

Partie I.1 — QCM SQL général (Questions 1 à 5)
Type : QCM & Analyse
Q1 : C) (Numetu, Numat)  --> Clé primaire composée de la table NOTES.
Q2 : C) Jours            --> DATEDIFF(d1, d2) retourne l'écart en nombre de jours.
Q3 : B) Retenir les étudiants ayant une note dans toutes les matières.
Q4 : C) IN compare une valeur à une liste, EXISTS teste l'existence de lignes.
Q5 : B) Pour comparer chaque note au maximum de sa propre matière (sous-requête corrélée).
Pourquoi l'utilisation de cette solution ? Dans NOTES, un étudiant possède une note par matière : le couple (Numetu, Numat) est donc nécessaire pour identifier chaque ligne de façon unique.
Partie I.2 — Commandes LDD (Questions 1 à 7)
Type : LDD : CREATE, ALTER, DROP
-- Q1 : LDD = Langage de Définition des Données (CREATE, ALTER, DROP, RENAME, TRUNCATE).
-- Q2 : Créer la table MATIERE :
CREATE TABLE MATIERE (
    Numat INT PRIMARY KEY,
    Nomat VARCHAR(50),
    Coeff INT,
    Numens INT,
    CONSTRAINT fk_matiere_enseignant FOREIGN KEY (Numens) REFERENCES ENSEIGNANT(Numens)
);
-- Q3 : Ajouter la colonne DateEvaluation à NOTES :
ALTER TABLE NOTES ADD DateEvaluation DATE;
-- Q4 : DROP TABLE supprime la table et sa structure ; TRUNCATE TABLE vide uniquement les lignes.
-- Q5 : Modifier le type de Note en DECIMAL(5,2) :
ALTER TABLE NOTES MODIFY Note DECIMAL(5,2);
-- Q6 : Ajouter la contrainte CHECK sur Note (entre 0 et 20) :
ALTER TABLE NOTES ADD CONSTRAINT ck_note CHECK (Note BETWEEN 0 AND 20);
-- Q7 : Supprimer la clé étrangère fk_matiere_enseignant :
ALTER TABLE MATIERE DROP FOREIGN KEY fk_matiere_enseignant;
Pourquoi l'utilisation de cette solution ? On utilise les instructions du LDD (CREATE TABLE et ALTER TABLE ... ADD / MODIFY / DROP) car ces opérations agissent directement sur le schéma des tables MATIERE et NOTES.
Partie I.3 — Vrai / Faux (Affirmations 1 à 5)
Type : Règles SQL
1. VRAI  (Cdsexe = 'H' filtre les garçons)
2. VRAI  (DISTINCT élimine les doublons dans SELECT)
3. FAUX  (WHERE ne peut pas contenir AVG() ; il faut utiliser HAVING après GROUP BY)
4. VRAI  (Une sous-requête corrélée dépend d'une colonne de la requête externe)
5. VRAI  (Sans condition de jointure WHERE a.x = b.x, on obtient un produit cartésien)
Pourquoi l'utilisation de cette solution ? La distinction fondamentale entre WHERE (filtrage ligne par ligne avant regroupement) et HAVING (filtrage sur une fonction d'agrégation après GROUP BY) est une règle essentielle du programme STI.

IV. Corrigé Partie II — Les 17 Requêtes SQL sur la base ÉTUDIANT

Requête 1 : Afficher le nom et la date de naissance des étudiants nés après le 01/01/2004.
Type : DateType : Sélection simple
SELECT Nometu, Dtnaiss
FROM ETUDIANT
WHERE Dtnaiss > '2004-01-01';
Pourquoi l'utilisation de cette solution ? Toutes les colonnes sont dans la table ETUDIANT : on filtre directement sur la colonne de type DATE au format ISO 'YYYY-MM-DD'.
Requête 2 : Afficher le code sexe et le nombre d'étudiants pour chaque sexe.
Type : GROUP BY
SELECT Cdsexe, COUNT(*) AS NbEtudiants
FROM ETUDIANT
GROUP BY Cdsexe;
Pourquoi l'utilisation de cette solution ? On regroupe les lignes de ETUDIANT par Cdsexe avec GROUP BY Cdsexe et on compte l'effectif de chaque groupe avec COUNT(*).
Requête 3 : Afficher le nom et le grade des enseignants qui assurent la matière 'Histoire'.
Type : Jointure
SELECT E.Nomens, E.Grade
FROM ENSEIGNANT E, MATIERE M
WHERE E.Numens = M.Numens
  AND M.Nomat = 'Histoire';
Pourquoi l'utilisation de cette solution ? Le nom et le grade sont dans ENSEIGNANT tandis que le libellé 'Histoire' est dans MATIERE : on utilise une jointure E.Numens = M.Numens dans WHERE.
Requête 4 : Afficher le nom et le coefficient des matières enseignées par un enseignant de grade 'MCF' ou 'Assistant'.
Type : Jointure
SELECT M.Nomat, M.Coeff
FROM MATIERE M, ENSEIGNANT E
WHERE M.Numens = E.Numens
  AND E.Grade IN ('MCF', 'Assistant');
Pourquoi l'utilisation de cette solution ? On relie MATIERE et ENSEIGNANT par la condition de jointure M.Numens = E.Numens et on filtre le grade avec IN ('MCF', 'Assistant').
Requête 5 : Afficher les noms des étudiants ayant obtenu une note strictement supérieure à 15 en 'Mathématiques'.
Type : Sous-requêteType : Jointure
SELECT Nometu
FROM ETUDIANT
WHERE Numetu IN (
    SELECT N.Numetu
    FROM NOTES N, MATIERE M
    WHERE N.Numat = M.Numat
      AND M.Nomat = 'Mathématiques'
      AND N.Note > 15
);
Pourquoi l'utilisation de cette solution ? On utilise une sous-requête avec IN (qui joint NOTES et MATIERE) pour isoler les numéros des étudiants ayant eu plus de 15 en Mathématiques, puis la requête principale affiche leur nom.
Requête 6 : Afficher les matières dont la moyenne des notes est supérieure ou égale à 12, ainsi que cette moyenne.
Type : JointureType : GROUP BY + HAVING
SELECT M.Nomat, AVG(N.Note) AS Moyenne
FROM MATIERE M, NOTES N
WHERE M.Numat = N.Numat
GROUP BY M.Numat, M.Nomat
HAVING AVG(N.Note) >= 12;
Pourquoi l'utilisation de cette solution ? On joint MATIERE et NOTES, on regroupe par matière avec GROUP BY, et comme la condition porte sur la moyenne AVG(N.Note), on utilise obligatoirement HAVING AVG(N.Note) >= 12.
Requête 7 : Afficher les enseignants (nom, grade, ancienneté) qui enseignent au moins 2 matières.
Type : JointureType : GROUP BY + HAVING
SELECT E.Nomens, E.Grade, E.Ancien
FROM ENSEIGNANT E, MATIERE M
WHERE E.Numens = M.Numens
GROUP BY E.Numens, E.Nomens, E.Grade, E.Ancien
HAVING COUNT(M.Numat) >= 2;
Pourquoi l'utilisation de cette solution ? Après la jointure entre ENSEIGNANT et MATIERE, on regroupe par enseignant (GROUP BY) et on filtre ceux qui comptent au moins 2 matières avec HAVING COUNT(M.Numat) >= 2.
Requête 8 : Afficher l'âge moyen des garçons et des filles au 1er janvier 2025.
Type : JointureType : DateType : GROUP BY
SELECT S.Lbsexe, AVG(DATEDIFF('2025-01-01', E.Dtnaiss) / 365) AS Age_Moyen
FROM SEXE S, ETUDIANT E
WHERE E.Cdsexe = S.Cdsexe
GROUP BY S.Cdsexe, S.Lbsexe;
Pourquoi l'utilisation de cette solution ? On combine une jointure E.Cdsexe = S.Cdsexe, la fonction de date DATEDIFF('2025-01-01', E.Dtnaiss) / 365 pour calculer l'âge de chaque étudiant, et un GROUP BY par sexe avec AVG().
Requête 9 : Afficher les étudiants (nom et numéro) qui n'ont aucune note dans la matière 'Sociologie'.
Type : Sous-requêteType : Jointure
SELECT E.Nometu, E.Numetu
FROM ETUDIANT E
WHERE E.Numetu NOT IN (
    SELECT N.Numetu
    FROM NOTES N, MATIERE M
    WHERE N.Numat = M.Numat
      AND M.Nomat = 'Sociologie'
);
Pourquoi l'utilisation de cette solution ? Pour exprimer l'absence de note (« aucune note en Sociologie »), on utilise une sous-requête avec NOT IN qui exclut les étudiants ayant une note enregistrée dans cette matière.
Requête 10 : Pour chaque étudiant, afficher son nom, son numéro, le nom de la matière et sa moyenne par matière, par ordre alphabétique.
Type : JointureType : GROUP BY
SELECT E.Nometu, E.Numetu, M.Nomat, AVG(N.Note) AS Moyenne
FROM ETUDIANT E, NOTES N, MATIERE M
WHERE E.Numetu = N.Numetu
  AND N.Numat = M.Numat
GROUP BY E.Numetu, E.Nometu, M.Numat, M.Nomat
ORDER BY E.Nometu ASC;
Pourquoi l'utilisation de cette solution ? On réalise une jointure à 3 tables (ETUDIANT, NOTES, MATIERE) dans WHERE, suivie d'un GROUP BY par étudiant et par matière, et d'un tri ORDER BY E.Nometu ASC.
Requête 11 : Afficher le nom, l'âge et le libellé du sexe des étudiants ayant obtenu en 'Informatique' une note supérieure à la moyenne générale d'Informatique.
Type : JointureType : Requête imbriquéeType : Date
SELECT E.Nometu, DATEDIFF(CURRENT_DATE, E.Dtnaiss) / 365 AS Age, S.Lbsexe, N.Note
FROM ETUDIANT E, SEXE S, NOTES N, MATIERE M
WHERE E.Cdsexe = S.Cdsexe
  AND E.Numetu = N.Numetu
  AND N.Numat = M.Numat
  AND M.Nomat = 'Informatique'
  AND N.Note > (
      SELECT AVG(N2.Note)
      FROM NOTES N2, MATIERE M2
      WHERE N2.Numat = M2.Numat
        AND M2.Nomat = 'Informatique'
  );
Pourquoi l'utilisation de cette solution ? Il faut comparer la note d'Informatique de chaque étudiant à la moyenne globale de la matière : la requête imbriquée calcule d'abord AVG(N2.Note) en Informatique, et la requête principale filtre avec N.Note > (...).
Requête 12 : Afficher les étudiants ayant une note dans toutes les matières, avec leur moyenne générale pondérée par les coefficients.
Type : JointureType : GROUP BY + HAVINGType : Sous-requête
SELECT E.Nometu, E.Numetu, SUM(N.Note * M.Coeff) / SUM(M.Coeff) AS Moyenne_Ponderee
FROM ETUDIANT E, NOTES N, MATIERE M
WHERE E.Numetu = N.Numetu
  AND N.Numat = M.Numat
GROUP BY E.Numetu, E.Nometu
HAVING COUNT(DISTINCT N.Numat) = (SELECT COUNT(*) FROM MATIERE)
ORDER BY E.Nometu ASC;
Pourquoi l'utilisation de cette solution ? On regroupe par étudiant (GROUP BY) pour calculer la moyenne pondérée SUM(N.Note * M.Coeff) / SUM(M.Coeff), et HAVING COUNT(DISTINCT N.Numat) = (SELECT COUNT(*) FROM MATIERE) vérifie qu'il a bien été évalué dans toutes les matières.
Requête 13 : Afficher les étudiants (nom, numéro, libellé sexe) dont la note en 'Informatique' est supérieure à leur propre note en 'Mathématiques'.
Type : JointureType : Requête imbriquée corrélée
SELECT E.Nometu, E.Numetu, S.Lbsexe
FROM ETUDIANT E, SEXE S, NOTES N1, MATIERE M1
WHERE E.Cdsexe = S.Cdsexe
  AND E.Numetu = N1.Numetu
  AND N1.Numat = M1.Numat
  AND M1.Nomat = 'Informatique'
  AND N1.Note > (
      SELECT N2.Note
      FROM NOTES N2, MATIERE M2
      WHERE N2.Numat = M2.Numat
        AND M2.Nomat = 'Mathématiques'
        AND N2.Numetu = E.Numetu
  );
Pourquoi l'utilisation de cette solution ? On utilise une requête imbriquée corrélée (reliée à l'étudiant courant par N2.Numetu = E.Numetu) pour récupérer la note de Mathématiques du même étudiant et la comparer à sa note d'Informatique.
Requête 14 : Afficher les couples (Nom_Garcon, Nom_Fille) dont la différence d'âge ne dépasse pas 180 jours.
Type : Auto-jointureType : Date
SELECT DISTINCT E1.Nometu AS Nom_Garcon, E2.Nometu AS Nom_Fille
FROM ETUDIANT E1, ETUDIANT E2
WHERE E1.Cdsexe = 'H'
  AND E2.Cdsexe = 'F'
  AND ABS(DATEDIFF(E1.Dtnaiss, E2.Dtnaiss)) <= 180;
Pourquoi l'utilisation de cette solution ? On compare deux lignes de la même table ETUDIANT : on réalise une auto-jointure avec deux alias E1 (garçons) et E2 (filles) et on teste l'écart en jours avec ABS(DATEDIFF(E1.Dtnaiss, E2.Dtnaiss)) <= 180.
Requête 15 : Pour chaque matière, afficher le nom de la matière, la meilleure note obtenue et le nom de l'étudiant qui l'a obtenue.
Type : JointureType : Requête imbriquée corrélée
SELECT M.Nomat, N.Note AS Meilleure_Note, E.Nometu
FROM MATIERE M, NOTES N, ETUDIANT E
WHERE N.Numat = M.Numat
  AND E.Numetu = N.Numetu
  AND N.Note = (
      SELECT MAX(N2.Note)
      FROM NOTES N2
      WHERE N2.Numat = M.Numat
  );
Pourquoi l'utilisation de cette solution ? Pour obtenir à la fois la meilleure note de chaque matière et le nom du lauréat, on utilise une requête imbriquée corrélée (SELECT MAX(N2.Note) FROM NOTES N2 WHERE N2.Numat = M.Numat).
Requête 16 : Afficher la moyenne des notes obtenues dans les matières enseignées par 'Ali Ben Salah', regroupée par sexe.
Type : JointureType : GROUP BY
SELECT S.Lbsexe, AVG(N.Note) AS Moyenne
FROM SEXE S, ETUDIANT E, NOTES N, MATIERE M, ENSEIGNANT G
WHERE S.Cdsexe = E.Cdsexe
  AND E.Numetu = N.Numetu
  AND N.Numat = M.Numat
  AND M.Numens = G.Numens
  AND UPPER(G.Nomens) = 'ALI BEN SALAH'
GROUP BY S.Cdsexe, S.Lbsexe;
Pourquoi l'utilisation de cette solution ? On relie les 5 tables par leurs clés dans WHERE pour filtrer les matières d'Ali Ben Salah, puis on regroupe par sexe avec GROUP BY S.Cdsexe, S.Lbsexe pour calculer AVG(N.Note).
Requête 17 : Augmenter à 4 le coefficient de la matière 'Informatique', puis supprimer les enseignants qui n'enseignent aucune matière.
Type : UPDATE & DELETEType : Sous-requête
-- a) Mise à jour du coefficient d'Informatique :
UPDATE MATIERE
SET Coeff = 4
WHERE Nomat = 'Informatique';

-- b) Suppression des enseignants sans matière :
DELETE FROM ENSEIGNANT
WHERE Numens NOT IN (
    SELECT DISTINCT Numens FROM MATIERE
);
Pourquoi l'utilisation de cette solution ? On utilise UPDATE ... SET Coeff = 4 pour modifier la ligne d'Informatique, puis DELETE FROM ENSEIGNANT combiné à une sous-requête NOT IN pour supprimer les enseignants qui ne figurent dans aucune ligne de MATIERE.
